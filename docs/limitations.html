Known Limitations

Leash 1.6.0 is a complete, self-hosted toolchain: the compiler is written in Leash, builds itself from a checked-in bootstrap seed with no Python, and passes an 88/88 output-parity corpus. The items below are the honest, currently-known limits of the platform — each is intentional, scoped, and stable for 1.x.

LimitationSeverityComment
leashed.py still exists (test oracle) 🟢 Low Acceptable — it's a test, not a toolchain.
serve_tls POSIX-only 🟡 Medium Windows only serves h2c. Documented.
3 stdlib modules without JVM 🟢 Low @from native (sockets/TLS/SQLite) is impossible without a shim.
HTTP/3 / QUIC 🟢 Low Not implemented, but nobody expects it in 1.x.

leashed.py still exists (test oracle)

The package-manager reference implementation leash/leashed.py is the only remaining Python in the repository. It is not part of the toolchain: the shipping leash pkg command is a full native port (see Package Manager), and leashed.py is kept solely as a differential-test oracle for tests/test_pkg.py / tests/test_leashed.py. It is never invoked by a normal build, compile, or run.

serve_tls is POSIX-only

The httpserver module's TLS listener, serve_tls(port, cert, key, handler) (and serve_tls_ex), is available on Linux, Linux ARM64, and macOS. On Windows the server is HTTP/2 cleartext (h2c) and HTTP/1.1 only — there is no TLS listener. This mirrors the underlying shim: Windows uses the WinHTTP-style stack while POSIX uses BSD sockets + OpenSSL. See the installthis/httpserver/README.md for the per-platform matrix.

3 stdlib modules without JVM support

The JVM target (--target jvm) supports the full core language and almost all of the standard library. Three modules are backed by @from native archives and therefore stay platform-bound: http (sockets/TLS), httpserver (sockets/TLS), and sql (SQLite). Importing them on the JVM works, but calling into a native body aborts with a clear not supported on the jvm target error rather than miscompiling — implementing them would require a JVM-side shim (e.g. java.net / JDBC), which is out of scope for 1.x.

HTTP/3 / QUIC

Neither the http client nor the httpserver speaks HTTP/3 or QUIC. HTTP/1.1 and HTTP/2 (h2c and h2-over-TLS) are fully supported; HTTP/3 is a deliberate non-goal for the 1.x series.

Documented here deliberately: shipping a compiler means being explicit about what it does not do. If any of these becomes important, open an issue at github.com/foksiny/leash.
