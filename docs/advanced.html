Advanced Topics

Memory model at a glance

Leash has one source language and several memory backends. On native targets the scoped arena is the default layout: allocation is an aligned bump, reclamation is a scope or loop rewind, and there is no tracing collector in the hot path. If your ownership pattern does not fit the arena's frame model, --gc selects the original mark-and-sweep collector. The JVM target is a separate case — it always uses the JVM's own garbage collector and ignores arena flags.

Mark-and-sweep GC (--gc)

When you opt out of the arena with --gc, Leash uses a custom mark-and-sweep collector with a slab allocator and hybrid root finding. Memory is managed automatically — there is no free() for the programmer to call. Since 1.0, container storage is unboxed and element-width-aware: a vec<int> is one raw 8-byte-per-element array (values stored inline, not heap-boxed), wide integers such as int<128> live inline at their exact width, and reference-typed elements (strings, structs, nested vectors) are stored as 8-byte handles. Element buffers of pointer-free types are allocated ATOMIC: the collector never scans them, so integer payloads cannot falsely pin unrelated objects and marking a vector costs nothing.

fnc main() : void {
    // In --gc mode strings and containers are collector-managed.
    name: string = "Leash";
    v: vec<int>;
    for i: int = 0; i < 1000; i = i + 1 {
        v.pushb(i);
    }
    show(name, " ", v.size);
}

Hybrid root finding

Globals and class statics are registered precisely by the compiler, plus conservative scanning of the calling thread's stack. Explicit roots use leash_gc_register_root() / leash_gc_unregister_root().

Automatic cycles

Collection runs when allocation since the last cycle exceeds a threshold, deferred while workers are busy. Steady-state peak stays near 2× live + 256 KB. Tune with LEASH_GC_AUTO=0; print exit stats with LEASH_GC_STATS=1.

Manual control

From Leash code, gc_collect() forces a cycle and gc_stats() reports allocator state. The C API adds leash_gc_print_stats().

Slab allocator

Per-size-class free lists with no per-object malloc and no lock while single-threaded. The runtime is compiled into every program; no external collector library is required.

Precise container tracing

Pointer-free vector/matrix/array buffers are never scanned; only buffers that can hold references are. Lazy buffers mean a vector that never grows costs one small header.

Type-aware

Strings, vectors, arrays, structs, classes and unions are all handled properly; mark traverses the type graph rather than guessing at word patterns.

Under the hood the mark phase is iterative (an explicit worklist over an open-addressed page directory) so deep object graphs cannot overflow the C stack. The collector is initialized automatically at program start, and all allocation goes through leash_gc_malloc / leash_gc_realloc unless a mode explicitly opts out.

No collector and smart auto-free

For low-level work, the nogc function modifier switches a function to C's malloc/free. The GC is not initialized for a nogc main (saving startup time), calling nogc from managed code produces a warning, and unsafe nogc suppresses the remaining safety checks. The global equivalent is --no-garbage-collector / -ngc, intended for embedded, real-time or minimal-binary scenarios.

# Manual heap for the whole program
leash run myprogram.lsh --no-garbage-collector
leash compile myprogram.lsh -ngc

--autofree is stricter: it disables the collector and frees everything for you. The compiler records every heap allocation (strings, vectors, matrices, class instances, buffers) in a per-function tracking array and emits a null-safe cleanup loop at function exit. Allocations that are returned to the caller are excluded from the free set, so returned values stay valid. The GC runtime is reduced to a thin malloc/free stub, which makes this mode attractive for FFI libraries and deterministic per-thread cleanup.

leash run myprogram.lsh --autofree
leash compile myprogram.lsh -af
leash compile myprogram.lsh --opt 3 -af
# config.lshc — enable per project
main: "src/main.lsh"
clibs: {}
imports: "imports/"
opt_level: "O3"
out_name: "myprogram"
autofree: true
Since 1.2.0 the self-hosted compiler implements --autofree and the to-dynamic / to-static library outputs natively — there is no Python fallback. C consumers of a Leash library call leash_init() once before any other library function; in --autofree builds returned values are excluded from the automatic free().

The scoped arena (default)

The arena backend is a scoped bump allocator, enabled by default for native builds. It replaces tracing with thread-local bump allocation and deterministic, scope-based reclamation: an allocation is an aligned bump plus bookkeeping, and leaving a function or an instrumented loop rewinds the bump and frees the blocks above its checkpoint. Release is O(blocks) with no per-object free, no heap scan, no lock and no stop-the-world pause. There is no borrow checker — correctness comes from compiler-emitted framing, escapes and root copies, backed by runtime checks.

leash run myprogram.lsh            # arena (default)
leash run myprogram.lsh --gc       # mark-and-sweep GC (opt-out)
leash compile myprogram.lsh        # arena (default)
leash compile myprogram.lsh --gc   # GC

# config.lshc — opt back into the collector
gc: true
Default and verified. In 2.0.0 the arena is the default native layout, not an experiment or a planned feature. Strict lifetime auditing is compile-or-fail, escape snapshots are on by default, frame-exit verification is on by default, and every staging read is resolved through a single coherent snapshot image.

Allocation model and lifetimes

Blocks

Malloc-backed thread-local blocks: 32 KB steady-state with a 4 KB lazy initial block (ARENA_BLOCK_SIZE / ARENA_INIT_BLOCK_SIZE). Strings use a 16-byte arena header (ARENA_STR_HDR) with a magic tag, so a payload pointer can never be confused with another kind of pointer.

Scopes

Generated code pushes a frame on entry and pops on exit. Eligible loops get checkpoints so temporaries are reclaimed at iteration boundaries instead of only at function exit.

Frameless fast paths

Allocation-free functions and loops skip framing/reset overhead entirely, so pure compute paths run at GC parity.

Plain pointers

A pointer is valid until its allocating frame or iteration exits (or until a loop reset reclaims that iteration). Pointers are plain C pointers with no collector metadata or barriers.

No zero-fill on allocation

The arena never traces its memory, so it does not memset what it hands out. Every skipped fill is covered by a verified “fully initialised before read” contract. Poison on reclaim is unchanged.

Per-thread ownership

Each worker owns its arena; its blocks and per-thread stage cache are released by a thread-local destructor on thread exit, not at process exit.

Escapes, staging and the root arena

Values that must outlive their allocating scope are copied, not borrowed. There is no borrow checker to annotate: the compiler either knows how to move a value safely or it refuses to compile the program.

  • Returns: strings, vectors, hashes, structs/classes (deep over heap-typed and nested fields), slices and multi-heap tuples are staged, the frame(s) pop, and the value is committed into the caller's frame.
  • Cheap staging: small escape payloads are staged on the C stack, inside the escape helper's own frame which outlives the scope pop; larger ones come from a small per-thread stage cache that recycles released stage blocks. The escape path therefore performs far fewer heap allocations than a malloc-per-value implementation.
  • Root slots: a value that outlives its frame — a global, or an outer local written from a loop body — is copied into the program-lifetime root arena and the slot keeps that root copy (leasharena_root_store_string, _vec_typed, _hash_typed, _blob). While the slot is the only owner, the copy is reused in place, so assigning to the same global in a loop does not grow the permanent footprint. The root arena is never rewound; it grows geometrically and releases a block once its owning slot is gone.
  • Caller-owned targets grow in the root arena: a vector or hash owned by a caller (a parameter or a global) must survive the growing frame, so the compiler emits rooted entry points — leash_sh_vec_reserve_rooted, leash_sh_vec_extend_rooted, leash_sh_vec_insertv_rooted, and leash_sh_hash_make_rooted (which relocates the table into the root arena and marks it rooted so later inserts allocate there too).
  • Persistent and concurrent data: spawn argument blocks and futures/async results are copied or rooted in the program-lifetime root arena so workers and callers read stable storage. The hand-off is one compact private transfer block (a leash_xfer header, the argument block and a small copy area): string arguments travel through it (leasharena_xfer_copy_string), containers and aggregates keep their root copies, and the worker releases the transfer immediately after unpacking (leasharena_adopt_string + leasharena_xfer_free). Root copies use the compiler's type tree for nested fields; a union is copied as its boxed value (tag plus payload bytes), not as a pointer.
  • Cross-thread root index: once the first worker is spawned, root blocks are linked into a process-wide registry and are not reclaimed until shutdown. A worker that misses in its own block index resolves the block through that registry and caches it locally; root sole strings grow by allocate-then-copy instead of realloc, so no other thread can observe a moved block. The registry links existing arena blocks, so it adds no per-block allocation.
  • Aliasing after a global store: storing a mutable container into a global re-points the source local at the global's root copy, so g = v; g.pushb(4) is visible through both names. Because the root copy is reused in place, g = v; g = X leaves v observing X's contents; GC mode keeps v pointing at the old vector. Strings are immutable/copy-on-write and are never re-pointed.
  • Growth: superseded oversize growth buffers are reclaimed only in specific cases (dedicated single-occupant blocks with no saved frame referencing them). Growth-heavy kernels may retain waste until scope reset; churn-heavy kernels benefit from whole-scope release.
Caller-owned targets and raw pointers. Native handles from @from externals are proven-safe (runtime provenance check); union heap payloads are rooted before boxing. Escaping &x pointees are root-allocated; libc heap pointers are provenance-checked foreign handles.

Safety model

Poison on reclaim

Every reclaimed scope/loop byte is filled with 0xDD, turning most use-after-scope reads into obvious corruption instead of silently valid-looking data. LEASH_ARENA_POISON=0 removes the memset cost once lifetimes are validated.

Strict frame checks

Scope underflow, unmatched exits, leasharena_exit_n beyond the current depth, and invalid or out-of-range loop-frame indices abort with diagnostics instead of corrupting state.

Frame-exit verification

By default, every registered global/static pointer slot is checked before a scope pop or loop reset. A slot that still points into the frame being reclaimed is a loud abort, not a silent dangling pointer.

Deep escape

Returned structs/classes deep-stage and deep-commit heap fields recursively, including nested fields. Recursive types use a compiler-emitted type tree; the runtime stages the reachable instance graph with an identity map, so a returned cycle points at the copied instances rather than dying with the frame.

Hardened realloc

leash_gc_realloc checks ownership before reading the header and aborts on a foreign pointer. Arena strings use a string-aware path preserving the magic tag and length; a shared string keeps its old buffer for other holders; a shrinking tip allocation zeroes the whole reclaimed tail. Absurd sizes and non-power-of-two alignments are rejected before bump arithmetic can wrap.

Alias-safe growth

When a string's buffer lives in a dedicated block and the appended piece aliases it (for example s = s + s), the runtime copies into a fresh buffer instead of moving the block through an in-place realloc.

Validated header layout. Every generic allocation carries a tagged 8-byte size header (bits 63–48 hold the 'LH' tag), and codegen's inline bump allocator writes the same tag. A shared, block-bounded validator rejects interior pointers, forged string lengths and corrupt totals before any copy, so codegen and runtime cannot drift apart.

Escape snapshots. Bounded byte snapshots of reclaimed blocks are enabled by default (LEASH_ARENA_ESCAPE_SNAPSHOT=0 disables them). A snapshot is invalidated as soon as its address range is reused, and every staging read — container headers, bucket chains, keys, string lengths and vector buffers — is resolved through the same single snapshot image, so a copied header can never be paired with bytes read back from a freed, reused block. Only the block’s bumped prefix is copied, not its full 32 KB capacity, which keeps churn cheap. Pointer-valued locals are registered as exact roots and unregistered on frame exit, which lets ETRACE walk the full root graph without seeding from the C stack.

The original lifetime bugs are fixed; the audit now rejects only proven-unsafe patterns. The three lifetime bugs found by the original corpus sweep (collections_lru, text_regex, llvm_ir) are fixed: field-read aliases are rooted, class instances keep their identity across root copies, and regex node chains no longer retain frame-local pointers. Raw pointers from @from externals are now proven-safe: a runtime provenance check allows C/static pointers and aborts on arena-frame pointers. Union payloads with heap variants are rooted before boxing. Escaping &x pointees are root-allocated and libc heap pointers are provenance-checked, so both are supported. Provenance also flows through locals, so proven-safe raw-pointer returns, globals, stores and worker arguments are accepted; only unprovable pointers are compile-time errors. Once a program spawns workers, root blocks are registered in a process-wide index and are not reclaimed until shutdown, so containers, classes and aggregates with heap fields can be shared with workers. Aggregate escape of a container whose producing frame has already popped is covered by tests/test_arena_escape_asan.c. Mutating a local whose address escaped also uses the rooted growth helpers, so a later frame cannot reclaim the buffer a worker is reading.

All arena knobs are environment variables read at process start; none changes the compiled program's observable output. They are diagnostics and tuning aids, not part of the language.

Fair GC-vs-arena comparisons: clear ~/.leash/shcache, do not overlap compiles with runs, interleave mode order, and record child CPU plus max peak RSS via /usr/bin/time -v. Prefer arena block-byte peaks for allocator-level truth — RSS is page-granular and noisy on small deltas.

Where the arena wins

  • Often wins: allocation/churn-heavy and short-lived-temporary workloads, loop bodies that reset per iteration or skip framing, and hash/string-heavy code at O2+/O3+. Whole-scope release avoids per-object frees, scans, GC barriers and pauses; outputs remain identical to GC mode.
  • Can lose or be noisy: growth-heavy kernels that retain superseded buffers or live data until scope reset, workloads dominated by live peak rather than churn, and tiny compute-bound kernels where allocator work is minimal. Page granularity can hide small allocator wins in RSS.
  • 1.9.0 interleaved suite (15 runs, O2): aggregate GC 0.417 s → arena 0.372 s (1.12× faster) with no RSS losses; allocation-heavy alloc_churn_loop and allocstress are 3–4× faster. O3 runs measured 1.11–1.24× aggregate speedup.
  • Representative historical RSS points (GC → arena, O2): allocstress 2.5 → 1.9 MB, vec_stress 3.9 → 3.4 MB, mem_copy 9.7 → 10.1 MB (14.0 MB before reclaim), string_concat 2.4 → 2.9 MB (per-iteration temporaries outlive loop survivors). Cross-run timing/RSS comparisons are environment-sensitive; see benchmarking/README.md.

Optimization levels and arena-exclusive optimizations

The -O level controls frontend/LLVM/runtime behavior as usual and also selects arena-aware behavior (compiled with -DLEASH_ARENA; -DLEASH_ARENA_O2 at O2/O3/O4/Os/Oz; -DLEASH_ARENA_O3 at O3/O4):

LevelArena behavior
O0 / O1Conservative runtime reserves and sizing for predictable behavior.
O2+Exact trip-count vector/collection reserves and arena-only hash pre-sizing (leash_sh_hash_reserve) where counts are provable.
O3+Nested counted-loop push analysis with hoisted reserves (never above a loop-local receiver), compact 24-byte hash nodes, and fused keys that build "<prefix>"+int directly in a stack buffer (leash_sh_hash_push_int / get_int), avoiding per-iteration temporary key strings. hash_lookup block bytes improved from 1,873,960 to 1,152,184; matrix_mul and matrix_transpose peaks also dropped.

C ABI and runtime API

Arena pointers are plain bump memory (strings keep the O(1) bsize prefix and a magic tag) with deterministic, pause-free behavior. The public API in leash/gc.h includes leasharena_enter/exit and slow paths, loop operations (leasharena_loop_enter/reset/exit), escape/stage/commit helpers (leasharena_escape_*, leasharena_stage_*/commit_*), root allocation and copies (leasharena_root_alloc*, leasharena_root_copy_*), and growth-reclaim support. Rooted container entry points are declared by the generated module for compiler use. C/FFI consumers should keep cross-call persistent data in the root arena and call leash_init() once before other library functions.

The compile-time lifetime audit

The audit is what makes the arena safe to use by default. It is compile-or-fail, never warning-only: the compiler copies or roots every value whose type it knows how to move, and only rejects the cases it cannot prove safe. A rejected program produces an E_ARENA_LIFETIME error with the offending location.

Annotate frames

Codegen emits an arena enter/exit pair around each allocating function and optional checkpoints around eligible loops. Frameless paths are proven allocation-free.

Classify escapes

Each value that crosses a pop boundary is classified: return, global store, loop-carried local, spawn argument, future result, or illegal cross-frame store.

Move or root

Legal escapes are staged and committed, copied into the root arena, or sent through the spawn transfer block using the compiler's type tree for nested fields.

Reject the unprovable

Only pointers whose provenance cannot be proven are fatal. Escaping addresses, libc heap pointers, proven-safe returns/globals/stores and proven worker arguments are made safe instead.

Reading a lifetime diagnostic

The same audit runs during compile and leash check, so editors see errors before a binary is built. A diagnostic gives a code, a location, a source snippet, and structured guidance:

error[E_ARENA_LIFETIME]: raw pointer passed to a worker cannot be kept alive by the spawn transfer
  --> /src/demo.lsh:2
   |
 1 | worker fnc w(p *int) : void { show(1); }
 2 | fnc relay(p *int) : void { spawn w(p); }
   |                            ^^^^^
   |
   = why: A worker may run after the spawner's frame is reclaimed.
   = help: Pass a string, container or aggregate argument; the compiler roots those by type before the worker starts.
   = trace: arena lifetime audit -> spawn argument scan -> raw pointer argument

why: explains the memory-safety reason, help: gives the usual fix, and trace: shows which audit pass found it. If the pointer really is stable (nil, a native handle, libc heap, or a rooted &local), keep it — provenance now flows through locals, so no workaround is needed. Otherwise return an owned value or let the compiler root the pointee by storing it in a typed container first.

Migration guide: GC to arena

Build with full checks

Remove any --gc / gc: true override. Run with LEASH_ARENA_POISON=1, LEASH_ARENA_VERIFY=1 and LEASH_ARENA_ESCAPE_SNAPSHOT=1 (all on by default) and enable LEASH_ARENA_STATS=1 to see scope and root peaks.

Fix audit errors, do not suppress them

Return values instead of storing frame-locals into caller-owned aggregates. Replace raw pointers with owned values or root storage. Union payloads with heap variants are rooted automatically before boxing.

Account for the global-store difference

After g = v, v and g share the root copy in the arena; in GC mode v kept the old vector. If your code relies on the GC behavior, keep the old value explicitly.

Measure, then tune

Compare with cleared ~/.leash/shcache and interleaved runs. Use O2+/O3+ for exact reserves and compact hash nodes. Only disable poison or snapshots for a final peak-speed measurement after lifetimes are validated.

Keep GC as a fallback

If a subsystem genuinely needs dynamic, cross-frame ownership the audit cannot model, build that program with --gc. Both modes ship in 2.0.0 and produce identical output.

Error handling and safety

Leash prioritizes developer experience with helpful diagnostics: static type checking, smart error tips, runtime union checks, and unique error codes for every warning. Safe code cannot form a dangling reference, read freed memory, or mutate through an implicit borrow — checked at compile time with no annotation burden.

The implicit borrow checker

The collector (in --gc mode) removes use-after-free for heap values, and the compiler adds an implicit borrow checker: ordinary code needs no extra syntax, but any operation that could dangle or corrupt memory is rejected with a unique error code. The arena replaces the collector with the lifetime audit above, but the same static rules about stack escapes and borrows still apply.

No use after deleteE009 — using a variable after del is an error. A del anywhere in a loop poisons the variable for the whole function, because a later textual use can still run first on the next iteration.
No double deleteE008 — deleting the same instance twice is rejected.

Custom error definitions

The error keyword defines a named error that can take arguments and evaluate a message expression when thrown. Throwing prints the message with file, line and column info and terminates with exit code 1, unless caught by a works block.

error ExpectedArguments(amount int, got int) -> "Expected " + tostring(amount) + " or more arguments but only got " + tostring(got) + ".";

fnc main(args string[]) {
    if args.size < 2 {
        throw ExpectedArguments(2, args.size);
    }
}

Works-otherwise error handling

works...otherwise catches errors while the compiler checks the block. Its contract is precise: identifier-resolution failures the checker sees inside the block — an undefined variable or unknown identifier — are captured and handled; what the block proves clean runs as written. Every other static error (a type mismatch, an unknown type, a bad call) is still reported at compile time. Runtime failures such as bounds violations or division by zero are not caught; they terminate the program. At runtime, control routes to the otherwise handler with the captured message in err.

fnc main() : void {
    works {
        a: int = unknown_var;  // normally an error
    } otherwise err {
        show("Error caught: ", err);
    }
    show("Program continues...");
}

The checker captures the first static error it sees in the block; codegen then knows at compile time which path is real. If a static error was captured, the otherwise block runs with err holding the message; if the block checked clean, the body runs and otherwise is skipped entirely. Either way the program is valid.

Program termination. Call exit(1) to terminate immediately with an exit code. It is available as a builtin on native and JVM targets.

Native library imports (FFI)

Leash imports functions from native libraries (.a or .so files) with the @from directive. This enables foreign function interface with C, C++, Rust, Zig and anything else that produces a static or shared library. The directive declares items as external and links the named library at build time; in --check mode it only affects type checking.

Declaring native items

Only signatures go inside the block: functions, typed globals, structs, unions, enums and type aliases. Parameter names use the ordinary name: Type form.

@from("mylib.a") {
    fnc add(a: int, b: int) : int;
    fnc scale(v: float<64>, k: float<64>) : float<64>;
    version: int;

    def Point : struct {
        x: int;
        y: int;
    };
    def Color : enum { RED, GREEN, BLUE };
    def MyInt : type int;
};

fnc main() : void {
    show(add(10, 20));  // 30
}

Building the native library

// math_utils.c
int add(int a, int b) {
    return a + b;
}
# Static archive
gcc -c math_utils.c -o math_utils.o
ar rcs libmath.a math_utils.o

# Or a shared object
gcc -shared -fPIC math_utils.c -o libmath.so

Unsafe code

The unsafe keyword disables runtime safety checks and static safety warnings within a function. Use it for bit manipulation, type punning through unions, and performance-critical code where check overhead is not wanted. It also works on class methods.

def Memory : union {
    i: int;
    f: float<64>;
};

unsafe fnc fabs(x float<64>) : float<64> {
    mem: Memory = x;
    mem.i = mem.i & 0x7FFFFFFFFFFFFFFF;  // Clear sign bit
    return mem.f;
}

Checks disabled by unsafe:

Runtime

Division-by-zero checks, union tag mismatch detection, null pointer dereference checks, and vector bounds checking.

Static

The static division-by-zero warning and static array bounds checks.

Use unsafe only when you truly need to bypass safety checks. Unsafe code can cause undefined behavior, crashes or memory corruption — and in arena builds it also bypasses the guarantees the lifetime audit enforces, so keep unsafe regions small and auditable.

C runtime optimizations

The Leash runtime (gc.c / gc.h) is compiled at -O2 with -ffunction-sections, so the linker dead-strips unused helpers and binaries carry only the runtime they touch. Shared native optimizations include:

#Optimization
1Function-pointer matrix dispatch — one indirect call per element-wise op instead of a switch.
24× loop unrolling with __builtin_prefetch.
3Reusable thread pool — lazily initialized, persists for the program lifetime.
4Cache-blocked operations — tiles that fit in L1.
5Vector batch utilities — bulk copy, reverse, sort (O(n log n)).
6Slab allocator — 16 KB slabs split into size-class cells with free-list reuse (GC mode); one live cell pins at most 16 KB.
7Iterative mark phase — explicit worklist over an open-addressed page directory (GC mode).
8Fast memcpy — thin wrapper with __restrict__ hints.
9Unboxed byte-addressed vectors (1.0) — raw element arrays at exact element width; inline fast paths for push/get/set/pop, calling the runtime only to grow.
10Big-integer runtime (1.0) — exact decimal formatting and parsing for int<N>/uint<N> up to 512 bits, schoolbook division over 32-bit limbs.
11Buffered showb (1.0) — output accumulates in a growable buffer flushed once at exit; vector elements unpack without separators.
12Portable stdin access (1.0) — generated code reaches stdin through leash_sh_stdin(), so Windows binaries build and run.

Editor support

Leash ships native syntax highlighting for popular editors in the syntax_highlighters/ directory. Character literals are highlighted as characters, not strings — braces inside single-quoted text such as '{' are never treated as {expr} interpolation.

Vim / Neovim

mkdir -p ~/.vim/syntax
cp syntax_highlighters/leash.vim ~/.vim/syntax/
# Add to .vimrc:
" au BufRead,BufNewFile *.lsh set filetype=leash

VS Code (with LSP support)

The VS Code extension provides syntax highlighting, real-time diagnostics, hover tooltips, go-to-definition and auto-completion. Diagnostics use leash check, including the arena lifetime audit. The offline regression suite has 9 checks (npm test), and npm run package builds a lean .vsix. See Editor support for settings and installation.

# Manual installation: copy to the VS Code extensions folder
# Windows: %USERPROFILE%\.vscode\extensions\leash
# macOS/Linux: ~/.vscode/extensions/leash

# Or build from source
cd syntax_highlighters/vscode
npm install
npm run compile

Emacs

mkdir -p ~/.emacs.d/lisp
cp syntax_highlighters/leash-mode.el ~/.emacs.d/lisp/
# Add to init.el:
;; (add-to-list 'load-path "~/.emacs.d/lisp/")
;; (require 'leash-mode)
