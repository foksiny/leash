Standard Library

Overview

The standard libraries provide common utilities like type widths, math functions, string manipulation, tuple containers, JSON, UTF-8, hex, Base64, UUID generation and a windowing API. An extended set covers collections, algorithms, text processing, cryptography, encoding, native HTTP/HTTPS networking, embedded SQL (SQLite), OpenGL rendering, date/time, math extensions, system helpers, logging and a programmatic LLVM IR builder for generating assembly text from within Leash itself.

Optional and modular

Install only the libraries you need, or write your own following the same conventions.

Consistent style

PascalCase classes with static or instance methods; errors reported through sentinel values or result fields instead of crashes.

Everywhere the language runs

Most modules are pure Leash; the FFI modules ship prebuilt archives for each platform and Java shims for the JVM.

Optional by design. The standard libraries are optional — you can install only the ones you need, or write your own libraries following the same patterns.

Installation

Install the libraries globally so any project can import them. The installer copies the contents of installthis/ into ~/.leash/libs/.

# Install all standard libraries globally
leash install installthis/

# Then import in any project
use types::*;
use utils::math::Math;
use utils::str::Str;

Install the libraries

Run leash install installthis/ once. The contents are copied into ~/.leash/libs/, where every project can reach them.

Import what you use

Add a use line at the top of your source file, for example use utils::math::Math; or use json::*;.

Call the API

Use the class's public static or instance methods and check their result fields where documented. Compile normally — no extra flags are needed for pure-Leash modules.

Tests for every module live under tests/stdlib/ — run them with python3 scripts/test_stdlib.py test.

Import syntax

Basic imports

Import a single public item or a whole module with use:

use tuple::Tuple;
use utils::str::Str;
use json::JsonValue;

// Import all public items
use json::*;

Private imports

Use priv use when you need a library inside a module but do not want to re-export it to your own importers: write priv use utils::str::*; instead of use utils::str::*;. The imported names remain usable in that module's own functions, including public ones, but importers of your module do not see them.

Nested paths

use mathx::stats::Stats;
use utils::string_helpers::capitalize;

Where the compiler looks

The compiler searches for modules in two locations:

  1. The local directory of the file containing the use statement (including subdirectories)
  2. The global libraries directory (~/.leash/libs/) — where installed libraries are available from anywhere

When you import a module, all its public definitions (structs, classes, enums, functions, templates, etc.) become available in your file. This makes it easy to organize code into reusable, namespaced modules. See the Package Manager page for installing third-party libraries.

JSON library (json.lsh)

A full JSON parser, serializer, and pretty-printer built entirely in Leash. It supports objects, arrays, strings (including \uXXXX escapes and surrogate pairs), integers, floats with exponents, booleans, and null. Errors are reported through an ok / err pair instead of crashing, so malformed input is easy to handle gracefully.

use json::*;

fnc main() : void {
    v: JsonValue = Json.parse("{\"name\": \"Leash\", \"year\": 2026}");
    if v.ok == false {
        show("parse error: " + v.err);
        return;
    }
    show(v.get("name").as_string());  // Leash
    show(v.get("year").as_int());     // 2026
    show(Json.pretty(v));              // pretty-printed
}

Construct JsonValues with struct initialization and compose them with set / push_back:

use json::*;

fnc main() : void {
    obj: JsonValue = JsonValue { typ: JsonType::JOBJECT, ok: true };

    show(Json.stringify(obj));  // {"msg":"built","count":7}
}

UTF library (utils/utf.lsh)

UTF-8 encoding and decoding utilities. Encoding accepts any code point and produces the canonical UTF-8 byte sequence; decoding validates the input and reports failures through a UtfDecoded struct instead of crashing. Surrogates and out-of-range code points are rejected, and overlong / malformed byte sequences are never accepted.

use utils::utf::*;

fnc main() : void {
    show(Utf.encode(0x1F600));               // 😀
    show(Utf.length("Aé😀"));               // 3 (code points)
    show(Utf.valid("Aé"));                  // true
    cps: vec<int<64>> = Utf.codepoints("Aé");
    show(Utf.from_codepoints(cps));          // "Aé"
}

Hex library (utils/hex.lsh)

Hexadecimal conversion utilities: digit mapping, string ↔ bytes, and string ↔ integer conversions. All parsing is case-insensitive and strict — invalid input yields an empty result or -1 instead of crashing.

use utils::hex::Hex;

fnc main() : void {
    show(Hex.from_int(255));               // "ff"
    show(Hex.to_int("0xDEADBEEF"));         // 3735928559
    show(Hex.from_int_pad(255, 8));         // "000000ff"
    bytes: vec<char> = Hex.to_bytes("deadbeef");
    show(bytes.size);
}

Base64 library (utils/base64.lsh)

Standard Base64 encoding and decoding (RFC 4648 alphabet). Decoding skips whitespace, enforces canonical padding, and rejects non-alphabet characters, leftover bits, and misplaced = signs — invalid input decodes to an empty result.

use utils::base64::Base64;

fnc main() : void {
    show(Base64.encode("foobar"));          // Zm9vYmFy
    show(Base64.decode("Zm9vYmFy"));          // foobar
    bytes: vec<char> = Base64.decode_bytes("Zg==");  // raw bytes of "f"
    show(bytes.size);
}

Hot reloader (hotreload.lsh)

The Reloader watches a Leash source file for changes and automatically re-runs it. This is particularly useful during development when you want a live-reload workflow — edit your code and see the results immediately without manually re-running the compiler.

use hotreload::Reloader;

fnc main() : void {
    r: Reloader = Reloader.new("main.lsh");

LLVM IR builder (llvm::ir)

Pure Leash, real LLVM text. A pure-Leash library for programmatically generating LLVM IR assembly text. Because it is written entirely in Leash (no FFI), it runs anywhere the stdlib does, and the emitted text can be handed straight to llvm-as, llc, or clang. It is a great fit for writing JIT stubs, experimenting with codegen, generating test IR, or building small DSL compilers entirely inside a Leash program.

You build a Module with a Builder, then call m.emit_text() to produce the full assembly. The builder tracks registers, basic blocks, and types for you, so the fluent API reads like an instruction stream.

use llvm::ir::Module;
use llvm::ir::Type;
use llvm::ir::Builder;
use llvm::ir::Value;
use llvm::ir::ICMP;

fnc main() : void {
    m: Module = Module.make("demo");
    b: Builder = Builder.make(m);
    b.function("add", Type.i32_type(), {Type.i32_type(), Type.i32_type()});
    b.block("entry");

}

HTTP client (http::http)

A native HTTP client speaking HTTP/1.1 and HTTP/2, built on a small C shim bound via the @from FFI directive. Cleartext http:// requests speak h2c (prior knowledge) through the *_h2 API; https:// offers ALPN and speaks h2 when the server selects it, falling back to HTTP/1.1 otherwise. Linux bundles OpenSSL statically into linux/liblshhttp.a (no extra packages needed); Windows uses the built-in WinHTTP API (which negotiates h2 itself on TLS); macOS users can rebuild the shim with Homebrew OpenSSL in one command (see installthis/http/README.md). Responses follow redirects automatically, decode chunked transfer encoding, and honor per-request timeouts. On the JVM target the same API rides a bundled Java shim over java.net.http (Java 11+): h2 still negotiates over TLS via ALPN, but h2c is unavailable, so cleartext *_h2 calls report proto = "http/1.1".

use http::http::*;

fnc main() : void {
    r: HttpResponse = Http.get("https://example.com/");
    if r.success() {
        show("status: ", r.status);
        show("server: ", r.header("Server"));
        show(r.body);
    } else {
        show("failed: ", r.err);
    }
}

HTTP server (httpserver::httpserver)

A native HTTP server speaking HTTP/1.1 and HTTP/2, built on a small C shim (lshhttpd) bound through @from — completing the web stack started by the http client. h2c arrives via client-preface detection on the same port (same handler contract); serve_tls adds a TLS listener where ALPN negotiates h2 or HTTP/1.1 per connection. Linux liblshhttpd.a bundles OpenSSL statically like the client archive; Windows uses the built-in SChannel stack (HTTP/1.1 over TLS) alongside h2c over Winsock2. On the JVM target the same API (handlers, reply_* helpers, serve_tls, shutdown()) rides a bundled Java shim over jdk.httpserver (Java 11+) speaking HTTP/1.1 only.

use httpserver::httpserver::*;

fnc handle(method string, path string, query string,
            headers string, body string) : int {
    if path == "/" {
        return HttpServer.reply(200, "text/html", "<h1>Hello from Leash!</h1>");
    }
    if HttpServer.path_matches(path, "/api/data") {
        q: HttpQuery = HttpServer.parse_query(query);
        return HttpServer.reply(200, "application/json",
            "{\"echo\": \"" + q.get("q") + "\"}");
    }
    return HttpServer.reply(404, "text/plain", "not found: " + path);
}

fnc main() : void {
    show("listening on http://localhost:8080 ...");
    HttpServer.serve(8080, &handle);   // blocks until HttpServer.shutdown()
}

OpenGL (opengl::opengl)

The OpenGL module is available on every target. Native backends use GLX/EGL on Linux (x86-64, x86 and ARM64), WGL on Windows x86-64, and CGL/AppKit on macOS (x86-64 and ARM64). Each backend offers an offscreen framebuffer with pixel readback and a real double-buffered window with keyboard and relative-mouse input; system libraries are loaded at runtime, so no development packages or linker flags are needed. The JVM target, which cannot load native libraries, uses a pure-Leash software renderer with the same Gl API (window and input methods are unavailable there). The voxel sandbox in examples/usecases/minecraft_clone.lsh opens a first-person window when a display is available (WASD move, mouse look, Shift sprint, Space jump, LMB mine, RMB place, 1–9 select, G/F mine/place as keyboard alternatives, R reset, Esc or the title-bar X to quit) and shows an uncapped FPS/frame-time counter with VSync disabled. Without a window it falls back to the deterministic offscreen renderer.

SQL database (sql::sql)

An embedded, zero-configuration SQL database powered by SQLite, bound through the @from FFI directive. The SQLite amalgamation is vendored into the package and statically compiled into each platform archive (linux/liblshsql.a, win/liblshsql.a), so nothing external needs to be installed. Databases are single files (or in-memory), with prepared statements, typed bindings, and transactions. On the JVM target the same API rides a bundled small SQL interpreter (leash/jvm/LeashSql.java) with SQLite's result codes, column typing, affinity rules and transaction semantics for the core surface (CREATE/INSERT/SELECT/UPDATE/DELETE/transactions); database files use the engine's own format there, not sqlite3 files.

use sql::sql::*;

fnc main() : void {
    db: Db = Db.open("app.db");
    db.exec("CREATE TABLE IF NOT EXISTS users (id INTEGER PRIMARY KEY, name TEXT, score REAL)");

    ins: Stmt = db.prepare("INSERT INTO users (name, score) VALUES (?, ?)");
    ins.bind_text(1, "alice");
    ins.bind_float(2, 91.5);
    while ins.step() { empty; }
    ins.finalize();

    res: QueryResult = db.query("SELECT id, name FROM users");
    foreach _, row in<vector> res.rows {
        show(row.get(0).as_int(), row.get(1).as_text());
    }
    db.close();
}

Usage patterns

Import narrowly

Prefer use module::Item; over wildcard imports in large programs; use priv use to keep a dependency private to your module.

Check result fields

Most parsers report failure through ok / err fields or sentinel values (-1, empty string) instead of throwing. Always check them.

Pure Leash first

Almost every module is plain Leash source. The http, httpserver and sql modules additionally bundle native archives and JVM shims.

Core builtins need no imports at all — show, vec, hash and tostring are always available:

fnc main() : void {
    values: vec<int> = (vec<int>){3, 1, 2};
    show(values.size);
    show(tostring(42));
}
Wide integers are built in. int<128> and wider types parse and print exact decimals without a library import; see the Types library above for the full width table.

Frequently asked questions

QuestionAnswer
Do I need to install all 100+ modules?No. Install installthis/ as a whole or copy only the directories you need into ~/.leash/libs/.
Where does use mylib::*; look?First next to the importing file (including subdirectories), then in ~/.leash/libs/.
Are there int8 / uint16 aliases?No. Use the built-in generic syntax int<8>, uint<16>, etc.
How do parsers report bad input?Through result fields or sentinels: JSON has ok/err, UTF returns UtfDecoded.ok, hex/base64/uuid return empty values or -1.
Which modules need native libraries?http, httpserver and sql. Prebuilt archives ship for each platform, and Java shims cover the JVM target.
Can I generate LLVM IR from Leash?Yes — the pure-Leash llvm::ir builder emits text for llvm-as, llc or clang.
How are the modules tested?Run python3 scripts/test_stdlib.py test; sources live under tests/stdlib/, and the LLVM IR output is verified with llvm-as.
