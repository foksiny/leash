Leash 2.2.0

Installation & Setup

Leash is a self-hosted, LLVM-based compiler. The only prerequisite is a working C compiler (clang or gcc) used for linking; the compiler itself ships as a native binary and needs no Python, LLVM development libraries, or pip. Version 2.0.0 compiles with the scoped arena as the default native memory layout, while --gc opts into the mark-and-sweep collector.

Leash was made with the help of AI, but its design and ideas come from a human. The AI’s role was to implement the language and toolchain and to write the documentation. The human and the AI stress-tested Leash — checking where it fails and where it wins, then fixing quirks as they were found — so bugs are addressed right away and features are kept stable and reliable.

Install Leash

Leash compiles itself. The repository ships a checked-in bootstrap seed (bootstrap/leash-<version>-target-*) that compiles the current sources; that binary then compiles itself and the result is bin/leashc. No Python, no pip, no LLVM development libraries.

Clone the repository

git clone https://github.com/foksiny/leash && cd leash

Build the compiler

The Python-free bootstrap takes roughly two to four minutes.

./scripts/bootstrap.sh

Verify the build

bin/leashc version
# leash 2.2.0 (self-hosted)
What gets built. The bootstrap performs a three-stage build and fixed-point check, then installs bin/leashc. You can repeat it at any time with leash self-host.

Rebuild the compiler from source

leash self-host   # 3-stage bootstrap + fixed-point check, reinstalls bin/leashc

Put leash on your PATH

Once bin/leashc exists, install the toolchain globally so leash / leashc work from any directory. The built-in installer builds the compiler into ~/.leash/bin and also installs the Leash runtime (the C sources programs are compiled against) to ~/.leash/leash and the bundled standard library to ~/.leash/libs, so the installed toolchain is self-contained.

# Option A (recommended): built-in global installer
leash install compiler
export PATH="$HOME/.leash/bin:$PATH"       # add to ~/.bashrc / ~/.zshrc (use $HOME, not ~)

# Option B: copy the binary onto your PATH
cp bin/leashc ~/.local/bin/leash          # works anywhere once Option A has installed the runtime
cp bin/leashc ~/.local/bin/leashc

The compiler looks for its runtime next to the executable, then in ~/.leash/leash, then wherever LEASH_RUNTIME points — so a plain copy of the binary works from any directory once the global install has run (or while a repository checkout is nearby).

Use $HOME, not ~. Write export PATH="$HOME/.leash/bin:$PATH". The tilde stays literal inside quotes, and shells that do not expand it in PATH would break the compiler’s runtime lookups.

Windows (PowerShell)

# Option A (recommended): global installer
leash install compiler
$env:PATH = "$env:USERPROFILE\.leash\bin;$env:PATH"   # persist via System Settings

# Option B: copy onto PATH
Copy-Item bin\leashc.exe $env:USERPROFILE\bin\leash.exe

macOS

leash install compiler
export PATH="$HOME/.leash/bin:$PATH"

Afterwards, leash version (or leashc version) should print leash 2.2.0 (self-hosted) from any directory.

Your first program

Create hello.lsh with a main entry point. show writes its arguments to standard output.

fnc main() : void {
    show("Hello, Leash 2.0.0!");
}

Run it directly, then compile it to a standalone executable:

leash run hello.lsh
# Hello, Leash 2.0.0!

leash compile hello.lsh to hello
./hello
# Hello, Leash 2.0.0!
That’s the whole loop. Edit .lsh files, run with leash run while iterating, and compile with leash compile when you want a distributable binary. Memory uses the scoped arena by default; add --gc if you need the mark-and-sweep collector.

Running programs

You can run Leash files (.lsh) directly using the run command, or compile them to a native executable using the compile command. Leash also supports project-level workflows with init, build, and run (without a file) for larger projects with configuration files. The old runp command has been removed; use run without a file instead.

Direct execution

To execute a Leash program without creating an output binary (and optionally pass command line arguments):

leash run program.lsh [arguments...]
leash run program.lsh -- arg1 arg2

Compiling to a binary

# Default output (same name as input)
leash compile program.lsh
./program

# Custom output name
leash compile program.lsh to my_custom_binary
./my_custom_binary

# Link with external libraries
leash compile program.lsh -lm
leash run program.lsh -lcurl

Dynamic (.so/.dll) and static (.a/.lib) library outputs are built natively: leash compile program.lsh to-dynamic mylib / to-static mylib. C consumers link the library together with the Leash runtime and call leash_init() once before any other library function (see the compiler page for details).

Dumping LLVM IR

leash dump program.lsh

Project workflow

For anything larger than a scratch file, a project gives you a consistent layout and a single configuration file that drives builds and runs.

Project init (init)

The init command scaffolds a new Leash project with the standard directory structure, including a main entry point, import and output directories, and a project configuration file.

leash init my_project

Creates the standard project structure:

my_project/
├─ src/
│   └─ main.lsh          # Entry point
├─ imports/               # Local import directory
├─ out/                   # Compiled output directory
└─ config.lshc            # Project configuration

Generated main.lsh:

fnc main() |> show("Hello, World!");

Generated config.lshc:

main: "src/main.lsh"
clibs: {}
imports: "imports/"
opt_level: "O3"

Project build (build)

The build command reads config.lshc from the current directory and compiles the project. This uses the project configuration to find the main entry file, resolve imports, link C libraries, and apply the configured optimization level.

leash build
leash build --other-imports path/to/imports
leash build -oi path/to/imports

Project run (run without file)

The run command without a file argument compiles and runs a project in one step, using config.lshc. The output binary is temporary and cleaned up after execution, making it ideal for development and testing. The old runp command has been removed; run without a file is the supported form.

# Compile and run project (project mode)
leash run

# Pass arguments to the program (after --)
leash run -- arg1 arg2 arg3

# With additional import directories
leash run --other-imports path/to/imports -- arg1 arg2

# Run a single file (file mode)
leash run src/main.lsh -- arg1 arg2

Global install (install / rm)

Add a single-line global_install map to config.lshc, then run leash install with no arguments to compile each entry to a host binary in ~/.leash/bin/ (.exe on Windows) so it runs straight from the terminal. Remove them again with leash rm, which asks for confirmation first (an empty answer means yes).

global_install: {tester: src/main_test.lsh, tester_unsafe: src/main_test_unsafe.lsh}
leash install
leash rm tester tester_unsafe

Additional import paths

The --other-imports (or -oi) flag adds extra directories to the module search path for use ...; statements. This is available on compile, run, dump, and build. These directories are searched before ~/.leash/libs/, making it useful when working outside a project setup or when you need to import from non-standard locations.

leash compile program.lsh --other-imports mylibs/
leash run program.lsh -oi mylibs/ -oi other_libs/

Updating Leash

The update command checks for new releases on the Leash GitHub repository and pulls the latest changes. It fetches the latest release tag from github.com/foksiny/leash via the GitHub API, then runs git pull to update your local clone to the latest commit. Requires Git to be installed and the Leash repo to have been cloned from GitHub.

leash update

After a large update, rebuild the compiler so the installed binary matches the sources:

leash self-host

Troubleshooting

leash: command not found

The compiler is not on your PATH. Add $HOME/.leash/bin (see Put leash on your PATH) and open a new shell. Confirm with leash version, which should print leash 2.2.0 (self-hosted).

Runtime not found when running from a copied binary

The compiler searches next to the executable, then ~/.leash/leash, then LEASH_RUNTIME. Run leash install compiler once to install the runtime and stdlib, or point LEASH_RUNTIME at an existing checkout.

Linker errors such as cannot find -lclang

A C compiler is required for linking. Install clang or build-essential for your platform (see the prerequisites matrix), then retry the build.

A lifetime diagnostic like E_ARENA_LIFETIME

In the default arena, an unprovable raw-pointer escape is a compile error, not a warning. Proven-safe pointers (nil, &local, native handles and libc heap addresses) may be returned, stored, or passed to workers — the compiler roots the pointee for you. Return values by value when you can; use --gc only if you specifically want mark-and-sweep. See memory management modes.

JVM target fails with an async/spawn error

async and spawn on the jvm target need a Java 8 or newer runtime; everything else verifies on Java 5+. The arena is native-only — the JVM target uses its own GC.

Still stuck? leash check program.lsh --verbose prints detailed, step-by-step diagnostics, and leash help <command> documents each CLI command.

Editor support

The VS Code extension ships a full language server: completion, hover, go to definition, references, rename, semantic tokens, folding, inlay hints and compiler diagnostics. Diagnostics come from leash check, so arena lifetime errors appear as you type, with why: and help: text in the hover.

# Install the packaged extension (or use the VSIX from syntax_highlighters/vscode)
code --install-extension syntax_highlighters/vscode/leash-2.2.0.vsix --force
# From that directory: compile, lint and run the LSP regression suite
npm test

Point leash.lsp.executablePath at your compiler if it is not on PATH, and use leash.lsp.compilerArgs for flags such as --other-imports. The server sends those flags after check <file>, matching the compiler CLI.

SettingDefaultPurpose
leash.lsp.enabledtrueMaster switch for diagnostics.
leash.lsp.executablePathleashCompiler binary used for checks.
leash.lsp.compilerArgs[]Extra flags appended after the input file.
leash.lsp.diagnostics.modeonTypeChoose onType, onSave or onOpen.
leash.lsp.diagnostics.debounceMs500Delay before an on-type check.

The extension has an offline regression suite of 9 checks covering compiler argument order, parser and diagnostic formats, real leash check output (including E_ARENA_LIFETIME), macro/async parsing, new builtins and server startup with a minimal LSP client. Run it with npm test from the extension directory.

Tip. leash check file.lsh works on its own too: it type-checks and runs the arena audit without emitting a binary. This is the same path the editor uses.
