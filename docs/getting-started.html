Installation & Setup

Leash is a self-hosted, LLVM-based compiler. The only prerequisite is a working C compiler (clang or gcc) used for linking; the compiler itself ships as a native binary and needs no Python, LLVM development libraries, or pip.

Install Leash

Leash compiles itself. The repository ships a checked-in bootstrap seed (bootstrap/leash-1.6.1-target-*) that compiles the current sources; that binary then compiles itself and the result is bin/leashc. No Python, no pip, no LLVM development libraries.

# 1. Clone the repository
git clone https://github.com/foksiny/leash && cd leash

# 2. Build the compiler (Python-free, ~2-4 minutes)
./scripts/bootstrap.sh

# 3. Verify
bin/leashc version
# leash 1.6.1 (self-hosted)

Put leash on your PATH (global install)

Once bin/leashc exists, install the toolchain globally so leash / leashc work from any directory. The built-in installer builds the compiler into ~/.leash/bin and also installs the Leash runtime (the C sources programs are compiled against) to ~/.leash/leash and the bundled standard library to ~/.leash/libs, so the installed toolchain is self-contained:

# Option A (recommended): built-in global installer
leash install compiler
export PATH="$HOME/.leash/bin:$PATH"       # add to ~/.bashrc / ~/.zshrc (use $HOME, not ~)

# Option B: copy the binary onto your PATH
cp bin/leashc ~/.local/bin/leash          # works anywhere once Option A has installed the runtime
cp bin/leashc ~/.local/bin/leashc

The compiler looks for its runtime next to the executable, then in ~/.leash/leash, then wherever LEASH_RUNTIME points — so a plain copy of the binary works from any directory once the global install has run (or while a repository checkout is nearby). Use export PATH="$HOME/.leash/bin:$PATH" rather than "~/.leash/bin": the tilde stays literal inside quotes, and shells that don’t expand it in PATH would break the compiler’s lookups.

Windows (PowerShell)

# Option A (recommended): global installer
leash install compiler
$env:PATH = "$env:USERPROFILE\.leash\bin;$env:PATH"   # persist via System Settings

# Option B: copy onto PATH
Copy-Item bin\leashc.exe $env:USERPROFILE\bin\leash.exe

macOS

leash install compiler
export PATH="$HOME/.leash/bin:$PATH"

Afterwards, leash version (or leashc version) should print leash 1.6.1 (self-hosted) from any directory.

Rebuild the compiler from source

leash self-host   # 3-stage bootstrap + fixed-point check, reinstalls bin/leashc

Running Leash Programs

You can run Leash files (.lsh) directly using the run command, or compile them to a native executable using the compile command. Leash also supports project-level workflows with init, build, and run (without a file) for larger projects with configuration files. The old runp command has been removed; use run without a file instead.

Direct Execution

To execute a Leash program without creating an output binary (and optionally pass command line arguments):

leash run program.lsh [arguments...]
leash run program.lsh -- arg1 arg2

Compiling to a Binary

# Default output (same name as input)
leash compile program.lsh
./program

# Custom output name
leash compile program.lsh to my_custom_binary
./my_custom_binary

# Link with external libraries
leash compile program.lsh -lm
leash run program.lsh -lcurl

Dynamic (.so/.dll) and static (.a/.lib) library outputs are built natively: leash compile program.lsh to-dynamic mylib / to-static mylib. C consumers link the library together with the Leash runtime and call leash_init() once before any other library function (see the compiler page for details).

Dumping LLVM IR

leash dump program.lsh

Project Workflow

Project Init (init)

The init command scaffolds a new Leash project with the standard directory structure, including a main entry point, import and output directories, and a project configuration file. This provides a consistent starting point for any new Leash project.

leash init my_project

Creates the standard project structure:

my_project/
├─ src/
│   └─ main.lsh          # Entry point
├─ imports/               # Local import directory
├─ out/                   # Compiled output directory
└─ config.lshc            # Project configuration

Generated main.lsh:

fnc main |> show("Hello, World!");

Generated config.lshc:

main: "src/main.lsh"
clibs: {}
imports: "imports/"
opt_level: "O3"

Global Install (install / rm)

Add a single-line global_install map to config.lshc, then run leash install with no arguments to compile each entry to a host binary in ~/.leash/bin/ (.exe on Windows) so it runs straight from the terminal. Remove them again with leash rm, which asks for confirmation first (an empty answer means yes):

global_install: {tester: src/main_test.lsh, tester_unsafe: src/main_test_unsafe.lsh}
leash install
leash rm tester tester_unsafe

Project Build (build)

The build command reads config.lshc from the current directory and compiles the project. This uses the project configuration to find the main entry file, resolve imports, link C libraries, and apply the configured optimization level.

leash build
leash build --other-imports path/to/imports
leash build -oi path/to/imports

Project Run (run without file)

The run command without a file argument compiles and runs a project in one step, using config.lshc. The output binary is temporary and cleaned up after execution, making it ideal for development and testing. The old runp command has been removed; run without a file is the supported form.

# Compile and run project (project mode)
leash run

# Pass arguments to the program (after --)
leash run -- arg1 arg2 arg3

# With additional import directories
leash run --other-imports path/to/imports -- arg1 arg2

# Run a single file (file mode)
leash run src/main.lsh -- arg1 arg2

Updating Leash

The update command checks for new releases on the Leash GitHub repository and pulls the latest changes. It fetches the latest release tag from github.com/foksiny/leash via the GitHub API, then runs git pull to update your local clone to the latest commit. Requires Git to be installed and the Leash repo to have been cloned from GitHub.

leash update

Additional Import Paths

The --other-imports (or -oi) flag adds extra directories to the module search path for use ...; statements. This is available on compile, run, dump, and build. These directories are searched before ~/.leash/libs/, making it useful when working outside a project setup or when you need to import from non-standard locations.

leash compile program.lsh --other-imports mylibs/
leash run program.lsh -oi mylibs/ -oi other_libs/
