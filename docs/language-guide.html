Language Reference

Language at a glance

Leash is a general-purpose language built around a small, consistent set of ideas: explicit types with generous inference, containers that are part of the language rather than bolted on, and safety checks that the compiler inserts for you. This page is the authoritative description of the 2.0.0 syntax. Every code example is a complete program that type-checks against the 2.0.0 compiler.

Reads like pseudocode

fnc for functions, def for types, show for output, and optional semicolons. The first word of a declaration tells you its kind.

Safe by default

Bounds checks, union tags, non-null references and an implicit borrow checker. Opt out explicitly with unsafe when you truly need to.

Generic & composable

Templates, multi-type functions, operator definitions and macros let you build abstractions without giving up static checking.

Two targets, one source

Compile to a native binary or to JVM bytecode. The core language and standard library behave the same on both.

How to read this page. Each section moves from the short form you will write every day to the precise rules the compiler enforces. Reference tables are marked with a .table-wrap heading so you can skim them. If you are new to Leash, start with Installation & Setup, then come back here.

Program structure

Your first program

Every compiled application has an entry point named main returning void. Output uses the built-in show() function, which prints its arguments and appends a newline.

fnc main() : void {
  show("Hello, world!");
}

A function body is a sequence of statements inside braces. Statements declare variables, call functions, branch, loop, or return values. Braces group statements into a scope; a variable declared inside a scope disappears when that scope ends.

Write a .lsh file

Leash source files use the .lsh extension. A file may contain top-level definitions (functions, types, globals, imports) and exactly one entry point.

Check it

leashc compile program.lsh --check runs the full parser and type checker without producing a binary. This is what the documentation examples use.

Compile and run

leashc compile program.lsh -o program produces a native executable; leash run program.lsh builds and runs in one step. See Compiler & CLI for all flags.

Optional semicolons

Leash statements may end with a semicolon, but a newline terminates a statement just as well. Both styles are accepted everywhere, and the two can be mixed freely. This makes short scripts clean while still allowing several statements on one line when a semicolon is needed.

fnc main() : void {
  a: int = 10          // no semicolon needed
  b: int = 20;         // still perfectly valid
  c := a + b             // inference works too
  show(c)             // prints 30
  show(a, " ", b);  // semicolon separates on one line
}
Grammar separators keep their own rules. A semicolon is optional as a statement terminator, not as a grammar separator. C-style for headers (for i: int = 0; i < n; i = i + 1), struct fields, enum variants and union members retain their required separators. In a with { ... } block of declarations, use semicolons between declarations.

Comments

Leash supports line comments with // and block comments with /* ... */. Line comments run to the end of the line; block comments may span multiple lines and may be nested in most contexts.

// A line comment
/* A block comment
   across several lines */

fnc main() : void {
  show("code"); // trailing comment
}

Naming conventions

Identifiers start with a letter or underscore and may contain letters, digits and underscores. Names are case-sensitive. The compiler reserves language keywords such as fnc, def, if, struct and imut, so they cannot be used as variable names.

  • Variables and functions use lowerCamelCase — playerCount, fetchScore.
  • Types (structs, classes, enums, unions, aliases) use UpperCamelCase — Point, Person, Color.
  • Constants and macros use UPPER_SNAKE_CASE — MAX, PI.
  • Template parameters are conventionally a single uppercase letter — T, K, V.

Globals & visibility

Top-level variable declarations are module globals, accessible from every function in the same module. Globals are public by default; use pub to state that explicitly and priv to make a name module-private. Initializers are evaluated at program startup, before main runs.

pub app_name: string = "leash-demo";
priv counter: int = 0;

fnc bump() : int {
  counter = counter + 1;
  return counter;
}

fnc main() : void {
  show(app_name, " ", bump(), " ", bump());
}

Visibility also applies to functions, types and imports. A pub definition crosses module boundaries; a priv definition does not. This is what lets a module expose a small, intentional API while keeping helpers internal.

The three program-wide forms solve different problems: a regular global is shared state for one module, a function shared variable is a scoped hand-off between specific functions, and shared/fusion globals are for worker-thread communication. See Shared variables and Concurrency Model.

Variables & inference

A variable declaration names a type and, optionally, an initial value. The canonical form is name: Type = value. A declaration without an initializer is initialized to the type's default value.

fnc main() : void {
  a: int = 10;
  b: string = "Hello World";
  show(a, " ", b);
}

Auto-type inference (:=)

When the type is obvious from the initializer, the := operator lets the compiler infer it. This is syntactic sugar — the result is statically typed exactly as if you had written the type yourself.

fnc main() : void {
  a := 10;           // infers int
  name := "Leash";  // infers string
  xs := {1, 2, 3};   // infers int[3]
  show(a, " ", name, " ", xs);
}
Using := requires an initializer expression. The type cannot be inferred without a value, so x := is a syntax error. A trailing semicolon is optional here as anywhere else (see Optional semicolons).

Default initialization

A declaration without an assignment receives a well-defined default: zero for numbers, false for booleans, the empty string for strings, empty containers for vectors and hashes, and a heap-allocated instance for class types (calling the default constructor when possible).

fnc main() : void {
  n: int;        // 0
  s: string;     // ""
  v: vec<int>;  // empty vector
  show(n, " [", s, "] ", v);
}

Immutable variables (imut)

The imut qualifier declares a value that cannot be reassigned after initialization. Function parameters can also be marked imut to guarantee they are not modified inside the body. This is stronger than a constant: it forbids mutation through the value as well.

fnc add(a imut int, b imut int) : int {
  return a + b;
}

fnc main() : void {
  a: imut int = 10;
  // a = 20;  // rejected: cannot assign to an immutable variable
  show(a, " ", add(10, 20));
}

Infectious immutability

A function may declare an imut return type. When that return value is assigned to a variable, the variable automatically becomes immutable — even if it was not declared imut. The promise travels with the value across function boundaries.

fnc imut_add(a imut int, b imut int) : imut int {
  return a + b;
}

fnc main() : void {
  c: int = imut_add(10, 20);
  // c = 50;  // rejected: c is now immutable
  show(c);
}

Leash has a compact set of primitive types plus explicit-width numeric types. Everything else — strings, containers, structs, classes — is built from these.

Explicit bit-width types

Integers and floats can specify an explicit bit width. Integers use native LLVM support for arbitrary widths; floats are mapped to the closest standard hardware format (32-bit or 64-bit). Supported ranges are int<1> to int<512>, uint<1> to uint<512>, and float<16> to float<128>.

fnc main() : void {
  flag: uint<1>;          // 1-bit, boolean-like
  half: float<16> = 1.0;  // 16-bit float
  pixel: uint<8> = 255;   // 8-bit integer
  big: int<512>;           // 512-bit integer
  show(flag, " ", pixel, " ", big);
}
Wide integers print exactly. Integers of every supported width are printed with full precision by show(); values wider than 64 bits are converted with full precision by the runtime rather than truncated.

Number literals

Leash accepts decimal, hexadecimal, binary and octal integer literals, and several floating-point forms.

fnc main() : void {
  a: int = 42;          // decimal
  b: int = 0xFF;        // hexadecimal
  c: int = 0b1010;      // binary
  d: int = 0o755;       // octal
  e: float = 1e10;      // scientific notation
  f: float = 0x1.5p3;   // hex float with binary exponent
  g: float = .5;        // leading dot (0.5)
  show(a, " ", b, " ", c, " ", d);
}

Booleans and characters

bool has exactly two values, true and false. char holds a single character in single quotes and supports the usual escape sequences. Characters convert to integers through an explicit cast when you need their encoded value.

fnc main() : void {
  ok: bool = true;
  ch: char = 'A';
  nl: char = '\n';
  code: int = (int)ch;
  show(ok, " ", ch, " ", code, " ", nl);
}

Type casting & conversions

Leash offers four conversion mechanisms, from low-level reinterpretation to fully checked parsing.

SyntaxUse caseSafety
expr as typeSafe numeric and class conversions, bit-width changesType-checked at compile time
(type)exprLow-level casts and bit manipulationAllows any cast; may be unsafe
toint() / tofloat() / tostring()String parsing and formattingRuntime parsing
scast()Anything-to-anything, verifiedRuntime checks; aborts on data loss
 
fnc main() : void {
  f: float = 3.99;
  i: int = (int)f;       // 3 (truncation)
  c: char = 'A';
  u: uint = (uint)c;     // 65 (ASCII)
  show(i, " ", u, " ", 10 as float);
}

The scast() function

scast(TargetType, value) converts between any two types but guards the conversion at runtime so that no information is silently lost. Unlike (type)expr, which truncates or wraps without complaint, scast() verifies the result and aborts with a descriptive error if the conversion would be lossy. Inside unsafe functions the checks are skipped and it degrades to a raw cast.

fnc main() : void {
  u: uint = scast(uint, 10);    // 10 (fits)
  i: int = scast(int, "42");    // 42 (strictly parsed)
  d: float = scast(float, 123);  // 123.0 (exact)
  s: string = scast(string, 42); // "42"
  show(u, " ", i, " ", d, " ", s);
}

Float → floatNarrowing is lossless (round-trip comparison)

String ↔ number and byte conversions

fnc main() : void {
  a: int = toint(int, "123");
  b: float<32> = tofloat(float<32>, "3.14159");
  s: string = tostring(123);
  n: int<64> = 1234;
  bytes: char[8] = inttobytes(sizeof(int<64>), n);
  restored: int<64> = bytestoint(sizeof(int<64>), bytes);
  show(a, " ", b, " ", s, " ", restored);
}

Introspection: sizeof() and typeof()

sizeof() returns the size in bytes of a type or expression, evaluated at compile time when possible. typeof() returns the type name of an expression as a string, known at compile time — useful for debugging and logging.

def Point : struct { x: int; y: int };

fnc main() : void {
  p: Point = Point {x: 1, y: 2};
  show(sizeof(int), " ", sizeof(Point));
  show(typeof(p), " ", typeof(1 + 2));
}

Restricted literal types

A restricted literal type (sometimes called a "weird type") accepts only the exact literal values listed in its declaration. It is a compile-time constraint: the value is stored as its underlying literal type, but assigning any other value is rejected, and a restricted value cannot be widened to its base type without declaring the same restricted type.

def zero : type 0;
def onetwo : type 1, 2;
def status : type "ok", "error", nil;
def magnitude : type -1, 0, 1;

fnc main() : void {
  a: zero = 0;       // accepted
  b: onetwo = 2;     // accepted
  s: status = nil;   // accepted
  u: status = s;     // accepted: same restricted type
  // a = 1;          // rejected: zero only allows 0
  // t: string = s;  // rejected: status is not string
  show(a, " ", b);
}
Restricted types are useful for modelling small closed domains — flags, protocol states, sentinel values — without a full enum. They can hold integers (including negatives), strings, booleans and nil.

nil & flow

nil is the null literal. It is used for nullable pointer values, as one of the allowed values of a restricted type, and as the "no mode" argument of certain builtins such as exec(). Leash does not have a general nullable reference type: ordinary values are always initialized, and the compiler's flow rules reject dereferencing a null pointer in safe code.

fnc main() : void {
  // nil selects the "capture output" mode of exec()
  out: string = exec("echo hello", nil);
  show(out);
}

Typed-zero fallback on input

The input builtins getint(), getfloat() and getstruct() never produce a null value: a malformed or empty line yields the typed zero for the destination (zero for numbers, empty strings for string fields). Flow after an input call is therefore always total — no null check is needed. See Input handling.

Avoid showing nil. Printing a bare nil value is rejected by the compiler's nil-show audit. Use nil only where a null pointer or a "no option" argument is expected, as in the example above.

Operators & expressions

Leash supports the full suite of arithmetic, comparison, bitwise and logical operators, plus language-specific membership and identity operators.

fnc main() : void {

  b: int = 3;
  show(a + b, " ", a - b, " ", a * b, " ", a / b, " ", a % b);
  show(a & b, " ", a | b, " ", a ^ b, " ", ~a);

Short-circuit evaluation. For && and ||, the right operand is evaluated only when necessary, so x != nil && *x > 0 is safe. Conditions in if/while must be bool expressions — there is no implicit truthiness.

Is-in operator (<>)

The <> operator checks whether a value exists within an array, returning true if found. For vectors, use the .isin() method instead.

fnc main() : void {
  nums: int[5] = {1, 2, 3, 4, 5};
  if 3 <> nums {
    show("3 is in the array");
  }
}

is / isnt

is and isnt serve two purposes: type checking and deep value comparison. For arrays, vectors and strings, value comparisons check every element (or the whole content), not just identity.

fnc main() : void {
  a: int = 10;
  s: string = "hi";
  if a is int { show("It's int!"); }
  if s isnt int { show("Not an int"); }
}

Ternary operator

The conditional operator condition ? a : b returns the matching branch. Both branches must have compatible types.

fnc main() : void {
  a: int = 10 == 10 ? 10 : 20;
  x: int = 5;
  result: string = x > 3 ? "big" : "small";
  show(a, " ", result);
}

Operator definitions (opdef)

Operator definitions extend existing types with new methods or overload existing operators. They work with built-in types (string, vec, …) and user-defined types alike. For a generic type such as vec<T>, use thisop.typ to refer to the inner type parameter.

opdef string.join(a string, b string) : string {
  return a + b;
}

opdef string.repeat(s string, n int) : string {
  result: string = "";
  for i: int = 0; i < n; i = i + 1 {
    result = result + s;
  }
  return result;
}

fnc main() : void {
  show("Hello, ".join("world!"));
  show("Hey".repeat(3));
}
opdef vec+(vec1 vec, vec2 vec) : vec {
  result: vec<thisop.typ>;
  foreach _, v in<vector> vec1 { result.pushb(v); }
  foreach _, v in<vector> vec2 { result.pushb(v); }
  return result;
}

fnc main() : void {
  a: vec<int>;
  b: vec<int>;
  a.pushb(1);
  b.pushb(2);
  result: vec<int> = a + b;
  show(result);
}

Control flow

Branching

Use if, also (like else if) and else for conditional branching. Conditions must be bool expressions.

fnc main() : void {
  a: int = 5;
  b: int = 10;
  if a < b {
    show("a is less than b");
  } also a > b {
    show("a is greater than b");
  } else {
    show("a is equal to b");
  }
}

Unless

unless is if with the condition inverted — the then-block runs when the condition is false. The alsou keyword inverts its branch's condition too.

fnc main() : void {
  failed: bool = false;
  pending: bool = true;
  unless failed {
    show("All is well");
  } alsou pending {
    show("Still waiting...");
  } else {
    show("Something happened");
  }
}

Loops

Leash provides while, C-style for, do…while and an infinite loop.

fnc main() : void {
  i: int = 0;
  while i < 3 { i = i + 1; }

  for j: int = 0; j < 3; j = j + 1 {
    show(j);
  }

  k: int = 0;
  do { k = k + 1; } while k < 3;

  loop {
    show(i);
    i = i + 1;
    if i > 5 { stop; }
  }
}

For-each

foreach iterates over arrays, vectors, matrices, strings and even struct fields using the in<type> syntax. The loop variable receives the index (or key), the second variable receives the value.

fnc main() : void {
  a: int[3] = {1, 2, 3};
  foreach index, value in<array> a {
    show(index, ": ", value);
  }

  v: vec<string>;
  v.pushb("x");
  v.pushb("y");
  foreach i, s in<vector> v {
    show(i, " ", s);
  }

  foreach i, c in<string> "hey" {
    show(i, " ", c);
  }
}

With — scoped variable blocks

The with statement declares one or more variables that exist only inside its block. They disappear at the end of the block, so the same name can be reused later.

fnc main() : void {
  with a: int = 10 {
    show(a);                  // 10
  }

  with {b: int = 10; c: int = 20} {
    show(b + c);              // 30
  }

  with a: int = 100 {
    show(a);                  // 100
  }
}

Variables declared with with are ordinary variables: they may be any type, use := inference and be reassigned inside the block. The scope is enforced at compile time — referencing one after its block ends is rejected.

Switch-case

Leash's switch supports integers, floats, booleans, strings and enums. Each case has its own { } block, so there is no fall-through.

fnc main() : void {
  x: int = 2;
  switch x {
    case 1 {
      show("one");
    }
    case 2 {
      show("two");
    }
    default {
      show("not one or two");
    }
  }
}

stop, continue, empty, ignore

stop exits the innermost loop, continue jumps to the next iteration. empty is a no-op placeholder. ignore immediately exits the current function with the default value for its return type, after running any deferred calls.

fnc maybe(x int) : int {
  if x < 0 { ignore; }
  return x;
}

fnc main() : void {
  for i: int = 0; i < 5; i = i + 1 {
    if i == 2 { continue; }
    if i == 4 { stop; }
    show(i);
  }
  empty;
  show(maybe(3));
}

Functions

Functions are declared with fnc, followed by the parameter list and return type. Parameters are written as name type (without a colon inside the parameter list).

// Standard function
fnc add(a int, b int) : int {
  return a + b;
}

// One-line form using the pipe operator (|>)
fnc multiply(a int, b int) : int |> return a * b;

// Void return is the default
fnc greet(name string) |> show("Hello, ", name);

fnc main() : void {
  show(add(2, 3), " ", multiply(2, 3));
  greet("Leash");
}

Optional parentheses

When a function takes no arguments, () may be omitted in both the definition and the call.

fnc greet {
  show("Hello!");
}

fnc getValue : int {
  return 42;
}

fnc main() : void {
  greet;
  x: int = getValue;
  show(x, " ", getValue());
}

Default and named arguments

Parameters with default values are optional at the call site. Required parameters must come before optional ones. Named arguments use name=value, which lets you skip earlier defaults.

fnc math(a int = 1, b int = 2, typ int = 0) : int {
  return a + b + typ;
}

fnc main() : void {
  show(math());              // 3 (all defaults)
  show(math(10, 20));       // 30 (positional)
  show(math(b=20, typ=2));  // 23 (a=1 default)
}

Multiple return values

A function can return a tuple of values. Under the hood the compiler constructs an LLVM struct and extracts each element on assignment. The number and types must match the declaration.

fnc add_sub(a int, b int) : (int, int) {
  return a + b, a - b;
}

fnc stats(a int, b int, c int) : (int, int, int) {
  return a + b + c, a * b * c, a - b - c;
}

fnc main() : void {
  sum, diff: int, int = add_sub(10, 4);
  s, p, d: int, int, int = stats(2, 3, 4);
  show(sum, " ", diff, " ", s, " ", p, " ", d);
}

Recursion

Recursive functions work like ordinary ones. Each call gets its own stack frame and locals, and the base case must return without recursing.

fnc factorial(n int) : int {
  if n <= 1 { return 1; }
  return n * factorial(n - 1);
}

fnc main() : void {
  show(factorial(5), " ", factorial(0));
}

Inline and nested functions

inline suggests that the compiler insert the body at the call site. Functions may also be declared inside other functions; they are scoped to their enclosing function and do not capture surrounding variables (no closure semantics).

inline fnc add(a int, b int) : int {
  return a + b;
}

fnc main() : void {
  fnc double(x int) : int {
    return x * 2;
  }
  show(add(1, 2), " ", double(21));
}

Deferred execution (defer)

defer schedules a call to run automatically when the current scope exits, even on an early return. Deferred calls execute in reverse order (last scheduled, first run).

fnc cleanup() : void {
  show("cleanup");
}

fnc work() : void {
  defer cleanup();
  show("work");
}

fnc main() : void {
  work();
}

Lambdas

Anonymous functions can be assigned to variables and passed around. A lambda's type is written fnc(param_types) : return_type.

fnc main() : void {
  add: fnc(int, int) : int = fnc(a int, b int) : int {
    return a + b;
  };
  show(add(1, 2));
}

Async functions

Declare a function with async fnc and every call returns a future<T> immediately while the body runs on a worker thread. await joins the future and produces the value T. See Concurrency Model for the full worker model.

async fnc fetch_score(user string) : int {
  return user.size * 10;
}

fnc main() : void {
  a := fetch_score("Ada");
  b := fetch_score("Bob");
  show(await a, " ", await b);
}
Async functions compose: an async fnc may call and await other async functions. spawn cannot be used on an async function (it already runs on a worker), and main cannot be async.

Command-line arguments

Declare main with an args string[] parameter to receive command-line arguments. show() accepts multiple values separated automatically.

fnc main(args string[]) : void {
  show("Received ", args.size, " arguments");
  foreach i, arg in<array> args {
    show(i, ": ", arg);
  }
}

Shared variables

A function can declare shared variables in its signature, after the return type and before the body. A shared variable is one piece of program-wide storage with a declared type, and only functions that name it may read or write it. Two functions declaring the same name share the same storage — a helper can hand a result back without threading it through a return value.

fnc add(a int, b int) : void | result: int {
  result = a + b;
}

fnc gresult() : int | result: int {
  return result;
}

fnc main() : void {
  add(10, 20);
  show(gresult());
}

Separate several shared variables with commas: | x: int, y: string. They are zero-initialized (a string starts as "", a container as empty). The declaration is the only way in: using a shared variable from a function that does not declare it, declaring two different types for the same name, colliding with a global, or naming an unknown type are all compile-time rejections. A shared variable cannot be imut.

Shared variables vs. shared / fusion globals

Shared variables carry no synchronization: they are for passing values between ordinary functions, not for coordinating threads. See Concurrency Model for the worker-oriented globals.

Imports & aliases (use / alias)

Leash organizes reusable code into modules (.lsh files). The use statement imports public definitions from another module. Select individual items with ::, or import everything public with ::*.

use hash::Hash; imports one type. use math::*; imports all public items. use utils::helpers::capitalize; follows a nested module path. Only pub definitions cross a module boundary unless you write priv use ....

Module and single-item aliases

The alias keyword gives an imported module (or a single item) a local name, so accesses can be qualified as alias.item without polluting the global namespace. use alias_tst alias math; imports a whole module under the local name math; use hash::Hash alias MyHash; renames one imported type. A zero-parameter form like def PI : macro() ... can omit parentheses at the call site.

A module alias is a wildcard import under the hood — all public items become available both as alias.item and as bare item. Prefer the qualified form to keep code explicit. Module resolution and dependency installation are covered in Package Manager.

Arrays

Data is sequentially packed into memory and constructed with inline lists. All arrays in Leash are runtime-sized structures ({ i64 size, ptr data }), so array sizes are evaluated at runtime.

fnc main() : void {
  a: int<64>[5] = {1, 2, 3, 4, 5};
  show(a.size);
  foreach index, value in<array> a {
    show(index, ": ", value);
  }
}

Indexing

Indices are bounds-checked at runtime. Negative indices wrap from the end: -1 is the last element, -N the first. An index beyond that range aborts with a runtime error, and a constant index outside [-N, N-1] is rejected at compile time.

fnc main() : void {
  a: int[5] = {1, 2, 3, 4, 5};
  show(a[-1]);  // last element: 5
}

Dynamic array sizes

Variables, member access and even arithmetic expressions may specify an array size at runtime.

fnc main() : void {
  n: int = 5;
  arr: int[n] = {1, 2, 3, 4, 5};
  show(arr.size);
}

Vectors

Vectors are dynamic arrays declared as vec<T>. They grow and shrink and provide a rich manipulation API.

fnc main() : void {
  v: vec<string>;
  v.pushb("first");
  v.pushb("second");
  v.pushf("start");
  show(v.size, " ", v.get(0));
  v.set(1, "middle");
  v.insert(1, "extra");
  show(v.isin("first"));
  v.clear();
  show(v.size);
}

Matrices

Matrices are dynamically sized, heap-allocated flat arrays that support element-wise math with automatic parallelisation. Allocation is 64-byte aligned for SIMD and cache-line friendliness, with function-pointer dispatch, 4× loop unrolling, prefetching, cache-blocked operations and a reusable thread pool.

fnc main() : void {
  m1: matrix<float> = {1.3, 2.1, 5.3};
  m2: matrix<float> = {2.4, 9.3, 4.2};
  result: matrix<float> = m1 + m2;
  foreach i, v in<matrix> result {
    show(i, ": ", v);
  }
}

Hash tables

Hash tables are key-value structures declared as hash<K, V>. They accept any value types, including pointers, classes, structs, unions and other hash tables.

fnc main() : void {
  persons: hash<string, int> = {"John Doe": 23, "Jane Doe": 24};
  show(persons["John Doe"]);
  persons["John Doe"] = 30;
  persons.push("Bob", 25);
  show(persons.isin("Bob"));
  keys: vec<string> = persons.keys();
  vals: vec<int> = persons.values();
  show(keys, " ", vals);
  persons.delete("Jane Doe");
}
Membership dispatch. h.isin("k") asks a hash about key membership; v.isin(x) asks a vector about value membership. The free-standing <> operator works on arrays, vectors and strings, but using it on a hash is a compile-time rejection — a hash is queried by key.

Nested containers

Containers compose freely: a vector of vectors prints recursively with show(), and each level keeps its own methods.

fnc main() : void {
  grid: vec<vec<int>>;
  row1: vec<int>;
  row1.pushb(1);
  row1.pushb(2);
  grid.pushb(row1);
  row2: vec<int>;
  row2.pushb(3);
  grid.pushb(row2);
  show(grid);
  show(grid.get(0).get(1));
}

Strings

String evaluation is native: concatenation, substring removal, indexing and length queries are all built into the language. Strings are stored as UTF-8 byte sequences.

fnc main() : void {
  a: string = "hello";
  b: string = "world";
  c: string = a + b;        // concatenation: "helloworld"
  removed: string = c - b;  // remove first occurrence: "hello"
  ch: char = c[1];           // character indexing: 'e'
  len: int = c.size;         // length in Unicode code points
  show(c, " ", removed, " ", ch, " ", len);
}

String methods

Method / propertyDescription
.start() / .start(n)First character, or the first n characters, as a new string (new in 2.0.0)
.end() / .end(n)Last character, or the last n characters, as a new string (new in 2.0.0)
.replace(old, new)Replace the first occurrence of old with new

  s: string = "Hello, world!";
  show(s.start());       // H
  show(s.start(5));    // Hello
  show(s.end());         // !
  show(s.end(6));      // world!
  show(s.replace("world", "Leash"));
  show(s.size, " ", s.bsize);
}

.size counts code points, not bytes: "é".size is 1 and "😀".size is 1, even though the UTF-8 encoding is longer. Byte-level operations still work on bytes: s[i] and foreach ... in<string> advance one byte at a time. When code mixes .size with indexing, use .bsize for the encoded length; Utf.length validates UTF-8 and returns the code-point count.

String interpolation

Any Leash expression enclosed in { } inside a double-quoted string is evaluated and converted to a string. Escape a literal brace with \{ or \}. Interpolation works only in double-quoted strings.

fnc double(x int) : int { return x * 2; }

fnc main() : void {
  a: int = 10;
  b: int = 20;
  show("{a} + {b} = {a + b}");
  show("{double(5)}");
  show("mylist isn't '\{1, 2, 3\}'");
}

Multi-line strings

Triple quotes (""" or ''') create multi-line strings. Single-quoted triple strings do not support interpolation.

fnc main() : void {
  poem: string = """Roses are red,
Violets are blue,
Leash is awesome!""";
  show(poem);
}

cstr() / lstr() and char arrays

Leash supports both managed string values and lower-level char[] slices. cstr() converts a string to a char[]; lstr() converts back. Mixed concatenation works automatically.

fnc main() : void {
  str: char[] = cstr("Hello World");
  s: string = lstr(str);
  foreach i, c in<string> s {
    show(i, ": ", c);
  }
  s = s + '!';
  s = s + cstr(" :D");
  show(s);
}

UTF-8 length and indexing

Because strings are UTF-8 byte sequences, code-point length and byte length can differ. Use .size for the former and .bsize for the latter, and remember that byte indexing steps through encoded bytes rather than characters.

fnc main() : void {
  a: string = "é";
  b: string = "😀";
  c: string = "héllo";
  show(a.size, " ", a.bsize);
  show(b.size, " ", b.bsize);
  show(c.size, " ", c.bsize);
}

Structs

Structs group different variables together. Declare them at the top level with def ... : struct. Leash can iterate across struct fields natively, unrolled at compile time.

def Point : struct {
  x: int;
  y: int;
};

fnc main() : void {
  p: Point = Point {x: 10, y: 20};
  p.x = 15;
  foreach name, value in<struct> p {
    show(name, ": ", value);
  }
}

Field default values

Struct fields may have defaults used when an initializer omits them.

def Person : struct {
  name: string = "John Doe";
  age:  int    = 23;
};

fnc main() : void {
  p1: Person = Person {};
  p2: Person = Person { name: "Jane" };
  p3: Person = Person { name: "Bob", age: 30 };
  show(p1, " ", p2, " ", p3);
}

Struct functions

Functions can be attached to a struct with fnc ... -> StructType. The function receives an implicit this pointer with no heap allocation or vtable dispatch.

def Person : struct { name: string };

fnc getName() : string -> Person {
  return this.name;
}

fnc main() : void {
  p: Person = Person {name: "Ada"};
  show(p.getName());
}

Pointers & references

Leash supports pointers for low-level memory work and efficient parameter passing. Prefer safe references (&T) over raw pointers (*T) for function parameters: they offer the same efficiency with better safety.

fnc main() : void {
  a: int = 10;
  p: *int = &a;
  show(*p);
  *p = 20;
  show(a);
}

Safe references

A parameter declared &T receives the argument's address automatically and auto-dereferences on use.

fnc increment(v &int) : void {
  v = v + 1;
}

fnc main() : void {
  a: int = 10;
  increment(a);
  show(a);
}

Pointer arithmetic and member access

Pointer arithmetic is supported on *char pointers for raw character data. Raw-pointer indexing and arithmetic require an unsafe fnc; -> accesses a field through a pointer.

unsafe fnc main() : void {
  s: *char = cstr("Hello");
  show(*(s + 1));
}
def Point : struct { x: int; y: int };

unsafe fnc print_point(p *Point) : void {
  show(p->x, " ", p->y);
}

unsafe fnc main() : void {
  pt: Point = Point {x: 10, y: 20};
  pp: *Point = &pt;
  print_point(pp);
}

Generic pointer syntax

pointer<T> is an alternative to *T, useful in complex generic types. It is canonicalized to *T at parse time, so the forms are interchangeable.

def Node : struct {
  value: int;
  next: pointer<Node>;
};

fnc main() : void {
  n: Node;
  show(n.value);
}

Unions

Unions let a variable hold different types at different times. Leash implements tagged unions: the active variant is tracked at runtime, and accessing an inactive variant triggers a runtime safety error.

def Value : union {
  i: int;
  f: float;
  s: string;
};

// Switching variants explicitly is type punning, so this demo is unsafe
unsafe fnc main() : void {
  v: Value = 42;        // auto-detects the 'i' variant
  show(v.cur);        // smart-prints the active variant
  v = "hello";          // switches to the 's' variant
  show(v.cur);
  v.f = 3.14;           // explicit variant access
  show(v.f);
}

tounion()

tounion(UnionType, value) explicitly wraps a value in a union type, typically with an inferred declaration. The compiler validates that the value matches one of the variants.

def Value : union {
  i: int;
  s: string;
};

fnc main() : void {
  v := tounion(Value, 45);
  show(v, " ", typeof(v));
}
Accessing an inactive variant — for example reading v.i while v.f is active — triggers a runtime safety error that prevents crashes or memory corruption.

Enums

Enums define named constants. They are represented as integers under the hood, provide a .name property for display, and are compatible with int.

def Color : enum {
  RED,
  GREEN,
  BLUE
};

fnc main() : void {
  c: Color = Color::RED;
  show(c, " ", c.name);
  v: int = c as int;
  show(v);
}

Custom values

Each member can carry a type annotation and a custom value: strings, integers, floats or booleans. When accessing a member with a custom value, use the member's type, not the enum type. Members without values default to sequential integers from zero.

def ErrorCodes : enum {
  OK: int = 0,
  NOT_FOUND: int = 404,
  SERVER_ERROR: int = 500
};

def Names : enum {
  PERSON1: string = "John Doe",
  PERSON2: string = "Jane Doe"
};

fnc main() : void {
  code: int = ErrorCodes::NOT_FOUND;
  name: string = Names::PERSON1;
  show(code, " ", name);
}

Type aliases

Custom names for existing types improve readability or create an abstraction layer.

def MyInt : type int;
def Pixel : type uint<8>;

fnc main() : void {
  a: MyInt = 10;
  p: Pixel = 255;
  show(a, " ", p);
}

Classes

Leash supports object-oriented programming through classes, which combine fields and methods. Use pub for publicly accessible members and priv for members only accessible inside the class. Non-static methods receive an implicit this pointer.

def Person : class {
  pub name: string;
  priv age: int;

  static pub fnc new(name string, age int) : Person {
    return Person { name: name, age: age };
  }

  pub fnc greet() : string {
    return "Hello, my name is " + this.name;
  }
};

fnc main() : void {
  p: Person = Person.new("John", 30);
  show(p.greet());
  p.name = "Jane";
}

Instances, constructors and destructors

create instantiates a class and calls its constructor (a method named like the class). A variable declared with a class type but no initializer is automatically heap-allocated with the default constructor. del deletes an instance, calling the destructor named DEL_ClassName.

def Math : class {
  pub Math() { show("created"); }
};

priv fnc DEL_Math() : void {
  show("Destroyed!");
}

fnc main() : void {
  m: Math = create Math();
  del m;
}

Custom values with VAL_

A class can define a method named VAL_ClassName returning string. It is called automatically when the instance is passed to show() or tostring().

def Person : class {
  pub name: string;

  pub fnc VAL_Person() : string {
    return "Person(" + this.name + ")";
  }
};

fnc main() : void {
  p: Person = Person { name: "Ada" };
  show(p);
}
The VAL_ method must be named VAL_ followed by the exact class name (for example VAL_Person for class Person) and must return string.

Inheritance and dynamic dispatch

Declare a child with def Child : class(Parent). Child classes inherit fields and methods and can override methods. Upcasting (child to parent) is implicit; downcasting uses an explicit cast. Calls dispatch dynamically through vtables. Mark a method imut fnc to prevent overrides.

def Animal : class {
  pub name: string;
  pub fnc talk() : void { show("No sounds"); }
};

def Dog : class(Animal) {
  pub fnc talk() : void { show("Bark Bark!"); }
};

fnc main() : void {
  a: Animal = Dog {};
  a.talk();
}

Class-based entry points

Instead of a top-level fnc main(), define a class named Main with a static fnc main method. The compiler generates the wrapper automatically.

def Main : class {
  static fnc main {
    show("Hello, world!");
  }
}

Generics & multi-type functions

Leash supports generic programming through templates. Declare a type parameter with def T : template, conventionally a single uppercase letter or a descriptive name such as KeyType.

def T : template;

fnc identity(x T) : T {
  return x;
}

fnc main() : void {
  show(identity<int>(42));
  show(identity<string>("hi"));
}

Generic classes

def K : template;
def V : template;

def Pair : class<K, V> {
  first: K;
  second: V;
}

fnc main() : void {
  p: Pair<int, string>;
  show(p.first, " ", p.second);
}

Multi-type functions

Write generic-like functions without declaring template parameters by listing allowed types in square brackets. Leash instantiates a specialized, fully type-checked version per concrete argument signature.

fnc add(a [int, float], b [int, float]) : [int, float] {
  return a + b;
}

fnc main() : void {
  i: int = add(10, 20);
  f: float = add(10.5, 20.5);
  show(i, " ", f);
}

Macros

Macros are reusable snippets expanded at compile time through textual substitution. They have no call overhead, arguments are evaluated each time they appear in the body, and macro parameters have no type constraints.

def MAX : macro(a, b) |> a < b ? b : a;

def CLAMP : macro(val, lo, hi) |> val < lo ? lo : (val > hi ? hi : val);

def PI : macro() |> 3.14159;

fnc main() : void {
  show(MAX(10, 20), " ", CLAMP(15, 0, 10), " ", PI, " ", PI());
}

Input handling

Leash's input builtins read from standard input. get() reads an entire line and returns a string, with an optional prompt. keyget() reads a single key press immediately without waiting for Enter, useful for menus and game controls.

fnc main() : void {
  name: string = get("What is your name? ");
  key: char = keyget();
  show(name, " pressed ", key);
}

Typed input: getint, getfloat, getstruct

getint() and getfloat() read a line and parse it as an integer or float. getstruct(Type, prompt) reads one line per scalar field of a struct. Each accepts an optional prompt, and a malformed or empty line yields the typed zero rather than a null value.

Output & formatting

show() prints its arguments separated automatically and appends a newline. The end keyword argument overrides the trailing sequence.

fnc main() : void {
  show("Hello", end="");
  show("World", end=", ");
  show("Done");
}

Buffered output (showb)

showb() prints arguments exactly as given, with no automatic separators or trailing newlines. It can unpack vectors and nested vectors recursively, which makes it powerful for grids and custom printers.

fnc main() : void {
  showb("Hello ");
  showb("World!\n");
  grid: vec<vec<uint<1>>>;
  grid.pushb((vec<uint<1>>){1, 0, 1});
  grid.pushb((vec<uint<1>>){0, 1, 0});
  foreach _, row in<vector> grid {
    showb(row);
    showb("\n");
  }
}

Structured printing

show() understands containers and prints them structurally: vectors, matrices and arrays as [a, b, c] (recursively for nested containers), structs as { name = apple, qty = 3 }, and booleans as true/false. String interpolation uses the same formatting rules.

fnc main() : void {
  v: vec<int>;
  v.pushb(1);
  v.pushb(2);
  show(v);
  big: uint<512> = 42;
  show(big);
  t: bool = 1 < 2;
  show(t);
}

The File type provides straightforward file access. Open a file with File.open(path, mode), read or write through the handle, and close it explicitly or with defer so it closes even on an early return.

fnc read_all(path string) : string {
  f: File = File.open(path, "r");
  defer f.close();
  return f.read();
}

fnc main() : void {
  // In a real program: show(read_all("notes.txt"));
  show("File API ready");
}

Random numbers, time and shell commands

Random numbers

fnc main() : void {
  seed(42);
  n: int = rand(-10, 10);
  f: float = randf(0, 2);
  name: string = choose("Alice", "Bob", "Charlie");
  show(n, " ", f, " ", name);
}

All randomness comes from a ChaCha20-based CSPRNG (RFC 8439, 64-bit counter, zero nonce). seed(n) selects a fully deterministic stream that is bit-identical on every backend (native and JVM); unseeded draws use OS entropy. Integer ranges use unbiased rejection sampling, randf draws full 53-bit mantissa precision, and the generator is thread-safe.

}

Error handling

Custom errors

Define an error with the error keyword. An error can take arguments and has a message expression evaluated when it is thrown. Throwing prints the message with file, line and column information and terminates with exit code 1 unless caught by works...otherwise.

error ExpectedArguments(amount int, got int) -> "Expected " + tostring(amount) + " or more arguments but only got " + tostring(got) + ".";

fnc main(args string[]) : void {
  if args.size < 2 {
    throw ExpectedArguments(2, args.size);
  }
}

Thrown errors are prefixed automatically by the runtime (for example Runtime error [DatabaseError]: ...), with the error's name riding in the message as its code, the same way static diagnostics carry LEASH-Exxx.

works...otherwise

works...otherwise catches errors while the compiler checks the block. Its contract: errors the checker sees inside the block are captured and handled; what the block proves clean runs as written. Identifier-resolution failures (an undefined variable or unknown identifier) are routed to otherwise with the captured message in err. Every other static error — a type mismatch, an unknown type, a bad call — is reported at compile time as usual. Runtime failures such as bounds violations or division by zero are not caught.

fnc main() : void {
  works {
    a: int = unknown_var;
  } otherwise err {
    show("Caught: ", err);
  }
  show("Program continues...");
}

If no error occurs, the otherwise block is skipped entirely. It is the language's pcall: err is the dynamic failure wearing a string costume — the message you would have crashed with, handed to your handler instead.

Unsafe code & memory notes

Unsafe functions

The unsafe keyword disables runtime safety checks and static safety warnings within a function. Use it for bit manipulation, type punning, raw pointers, or performance-critical code where the check overhead is unwanted. It also applies to class methods.

def Memory : union {
  i: int;
  f: float<64>;
};

unsafe fnc fabs(x float<64>) : float<64> {
  mem: Memory = x;
  mem.i = mem.i & 0x7FFFFFFFFFFFFFFF;  // clear sign bit
  return mem.f;
}

fnc main() : void {
  show(fabs(-3.5));
}

Use unsafe only when you truly need to bypass safety checks. Unsafe code can cause undefined behaviour, crashes or memory corruption. Safe Leash code cannot form a dangling reference, read freed memory or mutate through an implicit borrow — checked at compile time with zero annotation burden.

Memory management modes

By default native programs use the scoped arena: values are reclaimed when their frame or loop iteration exits, and only unprovable raw-pointer escapes are rejected. Alternative modes are selected at compile time: --gc uses mark-and-sweep collection, --autofree uses scope-based cleanup, and nogc disables GC for fully manual management (typically paired with unsafe). Spawned arguments, futures and async results escape into the program-lifetime root arena; once workers exist, root blocks are published process-wide so workers read stable storage. See Advanced Topics and Compiler & CLI.

Native library imports (FFI)

The @from directive declares items as external and links a native static or shared library, enabling FFI with C, C++, Rust and anything else that produces a .a or .so. Its body may contain external fnc declarations, globals and type definitions:

@from("mylib.so") { fnc add(a int, b int) : int; my_global: int; def Point : struct { x: int; y: int; }; } declares an external function, an external global and an external struct. Calls such as add(1, 2) then compile to calls into the library. Native modules are provided by the package manager; see Standard Library for the bundled HTTP, SQLite and other FFI-backed modules.

Portability. Native-library output is platform-bound. On the JVM target, importing a native module works but calling into it reports a clear not supported on the jvm target error rather than miscompiling.

Design rationale

Why the syntax looks the way it does — the reasoning behind choices that make Leash learnable rather than arbitrary.

<> asks a question; in<type> starts a loop

The containment operator <> is two arrows looking at its operands: x <> xs reads "is x among xs?" — the brackets point from the value toward the collection. Iteration is a different word entirely: foreach x in<vector> xs. Languages that overload in for both membership and iteration force you to remember which meaning applies; Leash gives each its own symbol, so code reads the way it runs.

Containment dispatch: <> vs .isin()

Both ask "is it there?", and the dispatch is categorical rather than arbitrary.

  • <> is the free-standing question about a collection's elements: strings, vectors and arrays.
  • .isin() is the method form: on a hash it means key membership (h.isin("k") — the question a hash answers); on a vector it is value membership.

Using <> on a hash is a compile-time rejection — a hash is queried by key, and the method form says so.

imut is a contract, and it is contagious

imut is a stronger promise than const in C or C++, Java's final or Rust's let: it forbids mutation through the value, not just reassignment. The promise is enforced by soundness rather than convention — an imut value cannot flow into a slot that could mutate it, so immutability travels with the value.

fnc sits in the fn/func/fun family

Short like Rust's fn, read like "function", and deliberately distinct from def: functions are declared with fnc, types with def, so a declaration's kind is the first word you read.

.size is a property; .size() is a method

Strings and vectors expose .size as a property — for a vector it is a direct read of the header's size field, no call. For a string it is the number of Unicode code points; the UTF-8 byte length is .bsize (silent alias .__bytesize). Matrices accept both .size and .size(). If the value is a field, it reads like one.

Common pitfalls

A short list of mistakes that trip up newcomers, with the rule that fixes each one.

Using a value as a condition

if count is not truthiness. Write if count > 0; conditions must be bool.

Forgetting the type on a parameter

Parameters are written name Type without a colon inside the list. fnc f(a: int) is not the function parameter syntax; use fnc f(a int).

Mixing code points and bytes

.size counts code points while indexing counts bytes. Use .bsize when computing an index into a UTF-8 string.

Assuming <> works on hashes

It does not. Hashes answer membership questions by key through .isin(key).

Showing nil

Printing a bare nil is rejected by the nil-show audit. Show a string describing the state instead.

Expecting closures from nested functions

Nested functions cannot capture variables from the enclosing scope. Pass values as parameters instead.

Using unsafe too broadly

Mark the smallest function that needs it, not the whole module. Safety checks are there for a reason.

Frequently asked questions

Do I need semicolons?

No. A newline terminates a statement. Semicolons are still accepted everywhere and are required only where the grammar uses them as separators, such as C-style for headers and lists of struct fields.

Why does my conditional fail to compile?

Conditions must be bool expressions. Leash does not treat 0, empty strings or null pointers as truthy, so if x with an integer x is a type mismatch. Write if x != 0.

What is the difference between <> and .isin()?

<> is the free-standing membership operator for arrays, vectors and strings. .isin() is the method form; on a hash it checks keys. See Design rationale.

How do I return more than one value?

Return a comma-separated list and declare a tuple return type, then assign to multiple variables: sum, diff: int, int = add_sub(10, 4).

Are strings byte arrays or Unicode?

Both views exist. Strings are stored as UTF-8 bytes; .size counts code points and .bsize counts bytes. Indexing and foreach ... in<string> advance one byte at a time, so use .bsize when mixing them.

How do I get the first or last characters of a string?

Use .start() / .end() for one character, or .start(n) / .end(n) for n characters. These were added in 2.0.0.

Are arrays fixed-size?

Array sizes are fixed after creation but evaluated at runtime, so int[n] with a variable n is valid. Use vec<T> when the size must change.

What happens on an out-of-bounds index?

Runtime bounds checking aborts with a descriptive error. Negative indices wrap from the end, and constant out-of-range indices are rejected at compile time.

Can I overload operators on my own types?

Yes. Use opdef to add extension methods or overload operators on built-in and user-defined types. Generic types use thisop.typ for the element type.

How do I share state between functions?

Declare a shared variable in each function's signature after the return type (| result: int). For worker communication use top-level shared or fusion globals instead.

Is there a nullable type?

No general nullable reference type. Use pointers for nullability, restricted literal types for small closed domains that include nil, and the input builtins' typed-zero fallback for parsing.

When should I use unsafe?

Only for low-level code that the safety checks cannot express: raw-pointer arithmetic, type punning through unions, or measured hot loops. Keep unsafe regions small and reviewed.

Can the same source run on the JVM?

Yes for the core language and most of the standard library. Native FFI bodies and matrices stay platform-bound; see Compiler & CLI for the exact support matrix.

What is the difference between def and fnc?

def declares a type, alias, macro or template; fnc declares a function. Reading the first word of a declaration always tells you its kind.

How do I make a variable constant?

Use imut: x: imut int = 10. It also works on parameters and return types, and immutability propagates to variables assigned from an imut return value.

Can I omit parentheses on function calls?

Yes, when the function takes no arguments. Both greet and greet() work, in definitions and calls.

How do default and named arguments interact?

Required parameters come first. Named arguments such as math(b=20, typ=2) let you skip earlier defaults and fill in only the ones you care about.

Do I need to free memory manually?

Not by default. Native programs use the scoped arena, which roots values that outlive a frame and audits raw pointers. --gc opts into mark-and-sweep if you want collector semantics, --autofree uses scope-based cleanup, and nogc is for fully manual management.

What does defer guarantee?

The deferred call runs when the current scope exits, including on early return and ignore. Multiple defers run in reverse order of declaration.

How do I print a struct or a vector?

Just call show(x). Containers print structurally, with nested containers formatted recursively. For classes, define VAL_ClassName to control the output.

What is a restricted literal type for?

It models a closed set of exact values — for example def status : type "ok", "error", nil. Any other value is a compile-time rejection.

How do macros differ from inline functions?

Macros are expanded textually at compile time with untyped parameters and no call overhead. Inline functions are still functions: they are type-checked normally and the compiler may inline their bodies as an optimization.

Can I write my own operators?

Yes. opdef adds extension methods and overloads to both built-in and user-defined types. Use thisop.typ when extending a generic type.
